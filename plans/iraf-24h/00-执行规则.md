## 1. 每个 tick 的执行算法（严格按序）

1. 读 `00-STATUS.json`，取**状态非 DONE/BLOCKED 的最小 id** 作为本轮步骤。
2. 读该步骤的 `NN-*.md`，按其中「步骤」执行；**一个 tick 只推进一个步骤**。
3. 跑该步骤的「验收」命令，把原始输出落盘到 `build/iraf-24h/<id>/`（`build/` 已在 .gitignore，属证据区，不提交）。
4. 全部验收通过 → `git add` **仅该步骤「涉及文件」列出的路径** → 按该步骤「提交信息」提交。
5. 回写 `00-STATUS.json`（status / evidence / commit / updated_at / note），并在 `00-日志.md` 追加一行。
6. 当轮未完成：status 置 `IN_PROGRESS`，note 写清卡点与下一步动作，**不要**提交半成品。
7. 全部步骤 DONE/BLOCKED 后：进入「收尾模式」——只做汇总、证据索引、缺口清单与文档整理，不再新增实现。

## 2. 硬规则（违反即视为本轮失败）

1. 安全铁律见仓库根 `AGENTS.md`；LLM/语音/远端服务不得直发运动或安全命令。
2. **禁止伪造成功**：拿不到真证据（板卡不可达、镜像源未声明、依赖缺失）时，状态只能是 `BLOCKED` 并写明原因，不得用 mock 顶替，也不得表述为"已验证"。
3. **不得放宽任何既有门禁**让测试通过；阈值只来自声明与实测。
4. **只 add 自己负责的路径**；禁止 `git stash` / `git checkout` / `git reset` / `git add -A` / `git add -f`。
   另一窗口正在改 `examples/demo3_arm/` 与仿真线脚本，**不得触碰**。
5. 重构数值/运动学代码必须逐位一致：先快照，再改，再比对（`joint_positions` 完全一致，位置量 ≤1e-9 m）。
6. 中文文档、中文注释、中文提交体；Conventional Commits 前缀用英文。
7. 每个 tick 结束必须运行全量单测并把「失败/错误数」写进日志；**基线以本战役第一次运行为准**（历史基线：4 项导入错误 + 1 项既有失败，回归只看失败数是否变化）。
8. 不推送远端（当前环境 push 受限）；不创建新的 cron 任务；不改 `deploy/*.service` 的既有服务定义。
9. 依赖集中声明：版本、标签、包清单、镜像源、路径一律进 `config/sdk/package_matrix.yaml` 与 `profiles/boards/*.yaml`，禁止散落硬编码。
10. 每步最多重试本 tick 内 2 次；仍失败即按第 1 节第 6 条转 `IN_PROGRESS`/`BLOCKED` 并说明。

## 5. 无人值守注意事项（定时任务环境）

1. 环境实测：`jq` **缺失**，`git` 与 `python3` 可用。读 JSON 摘要请用 `python3 -m json.tool <file>`，或把逻辑写进 `scripts/`/`build/iraf-24h/<id>/` 下的小脚本再执行。
2. 避免 `python3 -c "…"` 形式的行内脚本：在无人值守环境可能被安全策略拦截。步骤文件验收块里的 `python3 -c` 若被拦截，**不要**反复重试，改用 `python3 -m json.tool` 或落小脚本完成同一核对，并在 note 里写明替换原因。
3. 提交用 `git commit -m "…"` 或 `git commit -F <预先用 write_file 写好的文件>`；**不要用 heredoc**（`<<'MSG'`）形式，容易被拦截。
4. 提交前先把「本轮将 add 的路径 + 提交信息」写到 `build/iraf-24h/<id>/commit-plan.txt`；若 `git add`/`git commit` 被拦或失败，保留改动、状态置 `IN_PROGRESS`、在 note 写明「待人工确认提交」，下一轮先重试提交。
5. 每个 tick 结束后把本轮实际执行的命令与退出码追加到 `build/iraf-24h/<id>/commands.log`，便于人工审计。
6. **解释器口径（步骤 02 实测发现，必须遵守）**：cron 会话里默认的 `python3` 指向 Hermes venv（`3.11.15`，**没有** mujoco/numpy/grpc），用它跑仓库脚本与单测会得到不可比的基线。本战役一律显式使用 `/usr/bin/python3`（`3.10.12`）：
   `/usr/bin/python3 -m unittest discover -s tests/unit -t tests/unit`（配 `PYTHONPATH=src`）。
   历史基线以 `/usr/bin/python3` 的口径为准：步骤 01 为 `Ran 263 / failures=1 / errors=4`，步骤 02 为 `Ran 283 / failures=1 / errors=4`（+20 为步骤 02 新增用例），失败/错误集合逐项一致。
7. **调度器（2026-09-20 安装）**：Hermes 的 cron 不是独立进程，由 gateway 的 60 秒 ticker 驱动（`gateway/run.py::_start_cron_ticker`）。本机已安装并启用用户级 systemd 服务 `hermes-gateway.service`（`hermes gateway install`，linger 已启用，注销后仍运行）。
   运维命令：`hermes gateway status`、`hermes cron status`、`hermes cron list`、`hermes cron pause|resume 5f4c3edeb9e7`、需要立刻推进时 `hermes cron run 5f4c3edeb9e7`（下一个 tick 生效）。
   投递为 `local`（本机无消息平台，`deliver=origin` 解析失败是预期的）；每轮汇报写在 `build/iraf-24h/<id>/tick-report.md`，完整输出在 `~/.hermes/cron/output/5f4c3edeb9e7/`。
8. **内网地址不入库（AGENTS.md 2.7）**：提交物中不得出现内网 IP；本目录与设计文档中的主机/板卡一律写角色名（`<仿真主机>`、`<边缘板卡A>`、`<边缘板卡B>`），精确地址只保留在内部运维记录里。新增文本提交前用 `grep -rnE "10\.[0-9]+\.[0-9]+\.[0-9]+" `自查。
