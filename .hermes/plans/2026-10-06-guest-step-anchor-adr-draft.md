# ADR 草稿：guest 步进锚点（联合世界可复现性的最后一处通道）

状态：**草稿 / 待臂侧数据确认**（2026-10-06）
关联：`docs/debug/2026-09-24-joint-model-dog-arm.md` §11.87（需求闸门）、§11.88 量测⑱~㉒；本仓 `AGENTS.md` 1.4 / 2.3 / 2.4 / 6.6。

## 1. 问题（一句话）

联合世界里 guest（臂）把"前进一段时间"翻译成"等 owner 推进 count 步"，而
`_wait_for_guest_steps` 的目标是 **`target = 当前步 + count`（相对量）**：

```python
# src/iraf_adapters/mujoco/mujoco_backend.py:4285-4299
before = int(self.plant.step_index)
target = before + count          # 相对当前步
self.plant.wait_until(target, timeout=..., poll_seconds=timestep)
# 注释自述：owner（驻留线程）在 guest 等待期间并发推进 ⇒ 实际常常 > count（owner 领先）
```

⇒ 若植物**已在请求者前面**（owner 领先），下一次请求仍从**新的当前步**算起 ⇒
**领先量永不被纠正**。臂的轨迹相位由自增计数器给出
（`_move_trajectory`: `elapsed = step * timestep`，`step` 从 1 递增），
(循环计数 → 植物步号) 只是**平移** `S0 + k` ⇒ **只要 `S0` 差 Δ，整条臂轨迹相对植物步号平移 Δ**，
从此每个植物步上作用到植物上的控制量都不同 ⇒ 植物轨迹不同 ⇒ 下游（狗停靠初值）不同。

`S0` = "臂第一次写 ctrl 时植物恰好在哪一步"，由**主线（臂）与驻留线程（狗）的调度竞争**决定
⇒ 这正是 s02b 两条离散分支（~17% / ~8%）的成因候选。

## 2. 证据链（都已实测，不含推测）

| 量测 | 事实 |
|---|---|
| ⑱ | s03 内**首拍**即分叉：同一步号 14755、同植物状态、**取值不同** |
| ⑳ | s03 `state_before` **逐位相同**（2365801816）；`before=dispatch=14750`；首拍 14755 ⇒ 窗口只有 5 步 = 10 ms |
| ⑳ | 冒烟轮 5 元组：14750 `desired == q`（新调用 cycle-0）；15005 起 `desired` 恒为 home ⇒ 稳定段 `ctrl` 只由 (q,dq) 决定 |
| ㉒ | 臂侧**每个植物步都写** ctrl（≈500 Hz）；狗侧每 5 步（100 Hz），且狗侧写入格点**逐项稳定**（5 的整数倍） |
| 码 | `_advance_for(0)` 对 guest = `_wait_for_guest_steps(1)`；`_move_trajectory` 相位锚在自增计数器 |

⇒ 14755 的狗侧取值不同，只能是 **(q, dq) 先变**；而窗口内狗没写 ⇒ 只能是**臂侧**在该窗口写入不同。

## 3. 候选方案

### 方案 A：guest 侧绝对锚点（推荐先做）
- 契约：guest 的步进等待改用**绝对步号** `target = anchor + 已请求总量`，`anchor` = 该**段**开始时的步号。
- 领先（`before > expected`）时**显式失败**（`PlantError`，附"请求/实际/领先量"三个数字），
  而不是静默平移相位 —— 符合铁律 2.3（禁止静默漂）。
- 风险：owner 领先在现有实现里是**常态**（注释自述"常常 > count"）⇒ 直接失败会打爆整链。
  因此落地必须成对：**先**让闸门保证不越界（方案 B 的约束），**再**开 A 的严格断言。

### 方案 B：闸门不越界（结构性）
- 现状：驻留线程"推进到 `min(_targets)` **才停**"（`plant.py:187-189`）⇒ 允许越过"交接点"。
- 契约：在 guest 步骤**派发/交接**时，驻留必须停在**声明的交接步号**，不得跨过；
  "交接步号"由场景层声明（与 §11.87 同一套：`scene.plant_demand_gate` 旁的显式布尔）。
- 风险：`§11.87` 那次 ABBA 死锁的教训 —— 闸门内部**只读裸 `_step_index`**、持 `_gate_cond` 时**不得取 `_lock`**；
  新增约束不得引入新的锁序。

### 方案 C（备选）：把相位改为由植物步号派生
- 让 `_move_trajectory` 的 `elapsed` 取 `(plant.step_index - anchor_step) * dt` 并**声明锚点**，
  使"相位"与"调度"解耦。与 A 类似但改在 guest 的**轨迹层**而不是等待层。

## 4. 不可突破的约束（起草即生效）

1. **判据一律不动**（s02b 0.030 m / 2.0°、s04 0.06、s07 0.065）。
2. 不得让 owner 无法推进（§11.87 死锁已付出代价）；锁序纪律不变。
3. 必须**声明化**：缺声明即显式失败（`EXIT_DECLARATION`），不设隐式默认值改变行为。
4. 任何改动都必须在**同一变更**里更新 §11.87/§11.88 文档与架构图（铁律 6.6）。
5. 验收：**同配置连跑 2 轮逐位比对**（`reached_s`、`ctrl_digest`、臂侧摘要序列三项都要一致）+
   30 轮通过率批次；单轮通过不算验收。
