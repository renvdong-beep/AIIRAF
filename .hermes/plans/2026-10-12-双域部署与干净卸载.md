## 2. 设计要点

### 2.0 安装形态（2026-10-12 使用者口径，已落成声明）
IRAF 的安装交付物 = **SDK shell 脚本包**，两种形态、四个角色：

```
形态 A  single-ubuntu2204  一台 Ubuntu 22.04 全装（仿真 + 运行）→ 开发/单机演示/回归
形态 B  sim-x86            x86 Ubuntu 22.04，只提供仿真 Provider 与场景
        edge-intel         边缘 aarch64 Hyper 智能域（TaskFlow/Skill/Policy/AgentOSBridge）
        edge-motion        边缘 aarch64 Hyper 运控域（控制域 Capability Provider）
```
落地文件（**已实现并通过校验**）：
```
config/install/install_profiles.yaml          四角色的唯一事实来源（装什么/装到哪/起什么/怎么验残留）
config/install/install_profiles.schema.json   契约（draft-07，additionalProperties=false）
scripts/install_profile_check.py              只读校验入口（成功+拒绝路径，退出码 0/1/2）
tests/unit/test_install_profiles.py           13 例：成功路径 + 11 条拒绝路径
判据（实测 2026-10-12）：校验 54 项全过（exit=0）；单测 13/13 OK
```
声明驱动的三条硬约束（写进校验器，不靠人记）：
```
① 形态与架构绑定：single-*/sim-x86 必须 ubuntu 22.04 + x86_64；edge-* 必须 aarch64
② 仿真不得入边缘：edge-* 的 components 出现 adapters_sim 即失败（AGENTS 1.7/6.8）
③ 残留判据与服务清单同源：residue.units/ports 必须等于 services 里的单元与端口，
   漏一个单元 = 卸载后静默留下服务（这类"漏一处即静默失效"是本项目反复踩的坑）
另加两条交叉校验：版本来自 pyproject.toml 单一来源；端口事实必须与 deploy/iraf-runtime.env 一致
```

### 2.1 其余设计要点

```
① 域声明（先落声明再改脚本，铁律 2.1/5.3）
   新增 config/domains/<domain-id>.yaml（契约沿用 config/sdk/package_matrix.schema.json 风格）：
     域 id / 安装前缀与版本目录 / unit 名 / env 文件 / 进程入口（entrypoint + argv）/
     运行用户与权限 / 资源限额（CPU/Memory/IO）/ 设备所有权（我独占哪些设备）/
     跨域端点（上游/下游 + transport + 超时 + 重试上限）/ 依赖域（装载顺序）/
     数据目录（保留项，卸载不删）/ 残留判据（文件前缀、unit、端口、进程名）
   ⇒ 脚本只读声明；禁止在脚本/文档里再写一遍路径与端口
② Hyper 角色映射**只来自签名事实**（铁律 6.10）
   新增 scripts/board_collect.sh（**只读**采集）：uname/os-release/python/glibc/systemd/容器运行时/
   ROS2/CPU/RAM/磁盘/NPU/现场总线设备 + 签名 HyperProfile 与 Release manifest + /etc/iaros-version
   → 落 build/board/<board>/collect.json → 生成 profiles/boards/<board>.yaml 的回填补丁（人工审阅后提交）
   ⇒ VM 数量/编号/IP/OS/角色映射不得由我或脚本猜测
③ 预检 fail-closed（复用现成实现层，只加"域"这一层参数）
   架构/Python 标签/glibc/磁盘/RAM/依赖/systemd/unit 名冲突 + 板卡声明未 verified 必须显式 --allow-unverified
④ 卸载顺序与安全前提
   先智能域（上层）→ 后控制域；控制域卸载前**必须**确认没有在执行任务（有则显式失败，不"尽力而为"）；
   安全事件（QUARANTINED）未解除时拒绝卸载相关资源（铁律 1.9）
⑤ 卸载边界（回答"怎么保证干净"）
   只删：本域版本目录 + 本域 unit + 本域 env（全部来自本域安装记录）
   绝不：dpkg/dnf remove、删 AgentOS 自己的文件、删对方域的文件和记录
   数据默认保留（事件库/日志），`--purge` 才删且必须显式
⑥ 残留核验作为独立入口（不是卸载脚本的自证）
   scripts/verify_residue.sh --domain <id>：文件/目录/unit/env/端口/进程 六路扫描 → 全 0 才 exit 0
```

## 3. AgentOS CLI 接入（两种，走同一条 SkillRuntime 链，不产生第二套语义）

```
方式 A（推荐，最松耦合）：把 `iraf-agentos --json` 当一次外部工具调用
   入 {"text":"...","deadline_seconds":120,"resource_id":"...","request_id":"..."}
   出 与 AgentOSBridge 返回值同构的 JSON（status/error_code/execution_id/evidence）
   失败不改进程约定：仍出一行 JSON，退出码非 0（0 成功 / 1 执行或策略拒绝 / 2 用法环境 / 3 意图解析失败 / 4 Provider 不可达）
方式 B（生产）：常驻服务 iraf-runtime-http :8765 与 iraf-runtime-grpc :50051，
   AgentOS 只做"意图 → 任务提交/取消/订阅"，四个公共服务见 compatibility §2
铁律：AgentOS 不得拿 ROS topic / 厂家 SDK / 设备凭据（1.1/6.9）；身份只来自 AuthenticatedContext
```
