## 3. 根因（两条，互相独立）

### 根因 A（**可证明的声明缺陷**）：`min_swing_fraction` 与 `duty_factor` 在 duty = 0.75 处互斥

- 判据 `support_legs_profile`（本轮新增）与 ADR 决策 1 都要求「任意时刻 ≥ 3 条腿支撑」
  ⇒ 同一时刻至多 1 条腿离地 ⇒ 对单腿而言「离地比例 a ≤ 1/4 = 1 − duty」。
- 判据 `leg_*_clear_swing_cycles` 要求「一个周期内支撑相比例 ≤ 1 − min_swing_fraction = 0.75」
  ⇒ 「离地比例 a ≥ 0.25」。
- 两式合并 ⇒ **a 必须恰好等于 0.25**：该腿的离地窗口必须**铺满整个摆动窗口**，包括起落瞬间；
  且 ① 落地瞬间接触力必须立刻 ≥ 2 N、② 离地瞬间必须立刻 < 2 N（零卸载时间）。
  这与「连续轨迹两端高度为 0」+「任何有限卸载阈值」矛盾
  ⇒ **该判据在 duty = 0.75 下不可满足**（不是实现没调好）。
- 判据本身没有写反、也不是恒失败：合成序列的正例对照在把边界归属做成确定性后能通过
  （§4.2），说明它只是**零余量**。
- 处理方式（**未私自改**）：按战役规则登记为待人工决策，见 `plans/iraf-24h-2/00-STATUS.json` 的 02 note 与
  `config/go2_loopback.yaml` 里 `min_swing_fraction` 旁的 ⚠ 注释。

### 根因 B（**已定位，2026-09-21 补测**）：中立站姿的静态稳定余量 ≈ 0 ⇒ 命令抬腿会变成「机身翻倒 + 换腿离地」

- 与 trot 同形：单足接触力 200~450 N（砸台面）、第一个摆动周期即 4.20° 倾角、
  滚转每 0.2 s 符号交替并放大、最后走出台面。
- 已排除：摆动轨迹形状（sine/cosine 两组同形）、步高（0.08/0.10 同形）、
  接触序列结构（实测 `phase_sequence_structure` 通过）、相位/占空比声明（自洽门禁全过）。
- **已定位（见 §7）**：中立站姿下「抬单腿后的支撑三角形」对整机重心投影的余量只有
  **±0.000227483 m**（抬 RL/RR 时为负）——矩形站姿的对角线恒过中心，余量与站位宽度无关。
  静态三腿站立实测：命令抬 FL 时机身**翻 17.765°**并稳定在「RR 离地、FL 仍承载 44.46 N」的新位形 ⇒
  **机器人物理上抬的不是被命令的那条腿**，所以任何按声明相位结构写成的支撑相/离地判据
  都对不上实测接触模式。旧结论「是接触模型/初始穿台冲击/落地整形的组合」已由本轮三项对照推翻：
  穿台冲击只在起步 0.2 s 出现，而失效在第一个摆动周期内就已发生。

## 4. 本轮修复（与验收同文交付）

### 4.1 相位结构判据的**方向错误**（wave 才暴露）

`phase_sequence_structure` 把「后一组相位环按声明相位差平移后与前一组合」写成了 `+shift`，
而腿的相位是 `(u + offset) % 1`（offset 越大窗口在绝对相位轴上越**早**）⇒ 正确关系是
`current[k] == reference[(k + shift) % bins]`（本轮已改正）。
trot 的 Δ = 0.5 在环上**自逆**（`+10 ≡ −10 (mod 20)`），所以这个方向错误在 trot 下完全不可见。
证据：改正前三个相邻对的 `max_abs_diff` 全为 `1.0`，改正后为
`0.006651884700665134 / 0.011961722488038284 / 0.021052631578947323`
（`build/iraf-24h-2/02/diagnose-phase-structure.txt` 与 `…-fixed.txt`）。

### 4.2 合成夹具的相位边界浮点假象

`_samples` 夹具在 `duty = 0.75`、周期 0.8 s、采样 0.01 s 时每 0.04 s 就有一个采样点正好落在
支撑/摆动边界上，而 `1.25·t` 与 `(1.25·t + 0.25) % 1` 的浮点结果会一个落在边界内、一个落在外
（实测 t = 0.40：`u = 0.50000000000000000` 判支撑、`v = 0.75000000000000000` 判摆动；
证据 `build/iraf-24h-2/02/probe-phase-boundary.txt`）⇒ 合成序列出现「同一边界、两条腿归属相反」，
同时打掉相位结构与离地判据。夹具改为按边距归属（`phase < stance_frac − 1e-9`）。
**这不是放宽判据**：阈值一字未改，改的是夹具在边界上的确定性。

### 4.3 泛化与薄包装（声明驱动，不新增第二套实现）

- `gait.py`：`GAIT_KINDS = ("trot", "wave")`；占空比下限与相位结构**按 kind 分派**

  `trot_joint_targets` → `gait_joint_targets`、`assess_trot` → `assess_gait`（旧名留薄包装）。

  `scripts/verify_go2_trot_in_place.py` → `scripts/verify_go2_gait_in_place.py`（旧名薄包装、转发退出码）。

### 7.1 根因（几何，与控制器无关）：矩形站姿的支撑三角形余量 ≈ 0

```
/usr/bin/python3 scripts/probe_quadruped_support_margin.py --baseline config/go2_loopback.yaml \
    --json build/iraf-24h-2/02/support-margin.json      # 证据：build/iraf-24h-2/02/support-margin-report.txt
```

- 实测（中立站姿）：四足接触点 FL(+0.192156780,+0.142000000)、FR(+0.192156780,−0.142000000)、
  RL(−0.194643220,+0.142000000)、RR(−0.194643220,−0.142000000) ⇒ 站姿矩形 **0.3868 × 0.2840 m**；
  整机（15.596408 kg）重心投影 (−0.001627589, 0)，足端形心 (−0.001243220, 0)。
- 「抬单腿后支撑三角形」对重心投影的最小有符号余量：
  **FL +0.000227483 m、FR +0.000227483 m、RL −0.000227483 m、RR −0.000227483 m**。
- **这是几何必然，不是标定误差**：矩形站姿的两条对角线都穿过矩形中心，抬任意一条腿后，
  支撑三角形必有一条边就是那条对角线 ⇒ 只要重心投影落在矩形中心附近，余量恒 ≈ 0，
  **与站位宽度无关**（把腿站得更宽不会改善）。抬 RL/RR 时重心已在三角形**外**。
- 要拿到 +0.01 m 余量需要重心平移：FL (−0.005784, −0.007877)、RR (+0.006053, +0.008244) 米
  （方向 = 指向对角腿）。要落到支撑三角形形心（余量 ≈ 0.0611 m）需要 ≈ 0.08 m 量级的平移。
- ⇒ ADR-0008 决策 1 的理由句「≥3 条腿支撑 ⇒ **静态稳定、不需要平衡器**」**被本实测推翻**：
  三条腿支撑只是必要条件的"数目"，真正的静态稳定还要求重心在支撑多边形**内部且有余量**。

### 7.3 修法候选「重心平移」：**7/7 全败**（含机制正例对照）

| 形式 | 用例与数字 | 结果 |
|---|---|---|
| 正例对照（只验证机制） | 命令平移 (0.010, 0.010)、不抬腿 ⇒ 机身实测位移 (0.00561, 0.00370)、倾角 1.423°（σ 0.0001°）、四腿 39.65/37.81/38.35/36.79 N、饱和 0 | **机制生效但只兑现 56%/37%**（足端滑动 + PD 柔度） |
| 动态相位锁定平移（`trial_body_shift.py`，斜坡、两种相位顺序、各 3 档） | 对照 0：height_mean −62.236862（逐位复现既有判决）；as_declared 0.010/0.020 ⇒ −67.505887 / −75.402103；circular 0.010/0.020 ⇒ −55.307597 / −58.606555 | 全部 12/20 判据失败（仍倒下） |
| 静态大平移（`trial_static_three_leg.py`） | 抬 FL 0.08 + 平移 0.02/0.04/0.08（指向 RR）⇒ 高度 −7.60141 / −5.8362 / −18.82752 m | 全部翻倒 |

- ⇒ 「给足端目标加**运动学平移偏移**」这种**执行器形式**实现不了真实重心转移：平移量越大越糟。
  已实测的 `gait.stabilization`（速度阻尼，同样是足端目标偏移）第一轮也已被判为净失稳项——
  **两处失败同源**：足端被地面钉住时，机身系目标的平移只是给腿加内部死循环，不是推动机身。
- 未证明：如果改用「先迈脚/重新落点」或「机身位姿闭环」实现重心转移，wave 是否就能站住（见 §7.5 决策点）。

怀疑过「左右腿髋轴符号不一致导致侧向目标被镜像」：实测**四条腿**髋轴都是 `(1,0,0)`、
`Δfoot_y/Δq_hip` = +0.262309 / +0.267083 rad⁻¹（对称腿数值对称）、IK 的符号

### 7.5 工程结论与**人工决策点**（本步不得私自改设计）

两条"不用反馈"的路线都已被实测判死：动态 trot（26 组参数全败）、准静态 wave（静态前提不成立）。
而所有"靠关节空间足端目标偏移来推机身"的形态（速度阻尼、相位锁定平移）共 **7 例全败**。因此：

- **A**：wave + **迈步式**重心转移（靠足端重新落点/机身平面内真实移动 ≥5 cm 实现转移，再抬腿）。
  优点：仍不引入反馈；代价：要先做落点规划，且对扰动仍无鲁棒性（静态稳定 ≠ 抗扰）。

- **几何推导（与网格搜索互相独立）**：一对对角腿的两个支撑三角形共用**同一条对角线边**，

- **结论**：常量重心平移 ≡ 给四条腿加**同一个**常量足端目标偏移 ⇒ 该形式**不可能**让 wave 的

  也解释了为什么「平移量越大越糟」。

1. **法向力下界取 0 ⇒ 力旋量解不出可实现解**：识别信号是「力矩残差 == 目标力矩」（姿态力矩兑现为 0），

不能说明"平衡器能救回会翻的扰动"；② 隔离实验**翻倒之后的数字是混沌的**（同一用例两次跑
`height_mean` 分别为 −0.297318 与 −0.48841113966601235，而 `max_tilt` 两次相同 136.19406°）——
判据只认"是否翻倒"，不得引用翻倒后的均值做比较；③ 本轮**未回填任何能力**（`locomote` 仍未声明）；
④ 全部结论 `simulation=true`，真机/目标端 `DEFERRED`（板卡不在场）。

**根因（本轮最重要的新结论）**：mg 支撑按**实测接触力**判定的支撑集分摊 ⇒ 某腿在「该抬但还没抬」的时刻仍接触，
就被当成支撑腿并获得 ~mg/4 法向力，被**压在地面上**；又因支撑腿位置权重为 0，摆动轨迹也抬不动它 ⇒ **自锁**。
表现为「极其稳定但四足不离地」（tilt 0.28°、饱和 0、漂移 16 mm）——判据 `clear_swing_cycles` /
`stance_duty` / `tracking_error` **正确拦下**了「力控站立冒充行走」。

**连带修正一条读法**：隔离实验 5 mm 档本轮通过，但**不得读作「重心转移机制生效」**——B1 下位置级 sway
作用于支撑腿的通道已被关闭（权重 0），且四足被钉在地面 ⇒ 该档已不含摆动/重心转移动力学。此点登记为诚实边界。

**诚实边界**：① 全部结论 `simulation=true`，真机/目标端 `DEFERRED`（板卡不在场）；
② `locomote` **未回填**（20 项判据未全绿）；首期步态选择**无法作出**（两变体失败集合相同 ⇒ 无「先通过者」）；

④ trot 复评用的是**同一套 20 项判据**，未做任何口径调整。
