## 2. 原始数字（本机实测，逐字保留）

它自带的计时 `solve_time`（ms）：P50 **10.518** ｜ P95 **12.103** ｜ P99 **12.267** ｜ max **17.748** ｜ mean **10.078**
本机墙钟（ms）：P50 **12.306** ｜ P95 **13.918** ｜ P99 **14.102** ｜ max **19.965** ｜ mean **11.893**
相对预算（墙钟 P99 = 14.102 ms）：200 Hz（5 ms）**282.03%** ｜ 100 Hz（10 ms）**141.02%** ｜ 50 Hz（20 ms）**70.51%**

**作者数字不复现**：README L118 的"QP ≈1.67 ms / MPC 周期 ≈2.70 ms"在本机测不到；
本机 P50 10.518 ms（同一计时口径）是其声称值的 **6.3 倍**（10.518 / 1.67 = 6.30）。
按 ADR-0009 §4.6「不得引用他人性能数字」，以自测为准。可能原因（**无法从外部判定**）：
机器 / BLAS / OSQP 版本 / 预热状态不同。本条只作标注，**不得**用来解释掉本机数字。

## 3. 从它的源码读出的三条事实（决定口径，非推测）

证据文件：`build/research/mpc-repo/examples/examples__ex02_trot_forward.py`（行号即该文件行号）

1. **它的实际 MPC 更新率是 50 Hz，不是 48 Hz**
   - L65 `CTRL_HZ = 200`（控制拍 5 ms）；L79 `MPC_DT = GAIT_T / 16`；L80 `MPC_HZ = 1.0 / MPC_DT`；
     L81 `STEPS_PER_MPC = max(1, int(CTRL_HZ // MPC_HZ))`
   - ⇒ `int(200 // 48.0) = 4`（向下取整）；L217 `if (ctrl_i % STEPS_PER_MPC) == 0` 才求解
   - ⇒ 实际更新间隔 = 5 ms × 4 = **20.0 ms = 50.0 Hz**。
   - README L118 的"48 Hz real-time budget (20.8 ms)"是把 `MPC_DT = GAIT_T/16 = 0.0208333 s`
     画成图上的预算线（L316 `plot_solve_time(..., MPC_DT, MPC_HZ, ...)`），**不是**代码执行的周期。
2. **它的求解在控制拍内联、且主循环无实时节拍同步**
   - L203-231：MPC 求解在控制拍分支内联（阻塞该拍）；L199-306 全文无 sleep/同步，
     `mj_step` 每步固定推进 1 ms 仿真时间。
   - ⇒ 求解耗时在它那边表现为"仿真时间落后于墙钟"，**不构成 deadline 违约的观测**。
     照抄该结构到我们的 100 Hz 闭环 = 违反铁律 4 与 ADR-0009 §4.3/§4.4（重计算不得进实时闭环）。
3. **参考相位按实测时间推进**（L200 `time_now_s = float(mujoco_go2.data.time)`；
   L220-229 用 `time_now_s` 调 `generate_traj`，`time_step=MPC_DT` 只作为 MPC 内部离散化步长）
   - ⇒ 声明步频 3.0 Hz 精确成立，不随线程周期漂；`MPC_DT` 与线程周期的 4.17% 差异（20.8333 vs 20.0）
     是**它的实现事实**（L68-73 注释声称"clean decimation"但 200/48 = 4.1667 非整数），不是我们的缺陷。

## 4. 口径决策（本文即准；ADR-0009 §6.5 同文）

- **解耦口径**：MPC 独立进程/线程，更新周期 **20.0 ms（50 Hz）**，对齐声明的
  `control_frequency_hz = 100`（`profiles/unitree_go2_mujoco.yaml:12`）⇒ 每 2 拍更新一次；
  **不**与关节控制 100 Hz 同步、**不**在控制拍内联求解。
- **预算取值 = 20.0 ms**（不是 20.8333）：14.102 / 20.0 = **70.51%**（比它 README 口径 67.69% 更严）。
- **MPC 内部 dt 保持 `GAIT_T/16 = 0.0208333 s`**：16 × 0.0208333 = 0.333333 s = GAIT_T（整除是接触表相位的前提；
  改成 0.02 得 16 × 0.02 = 0.32 ≠ GAIT_T，每个 horizon 相位漂 13.33 ms）。
  参考相位按**实测时间**推进（同它 ex02）。
- **否决 100 Hz 同步支**：(a) 实测 141.02%，非口径可救；(b) 与铁律 4、ADR-0009 §4.3/§4.4 冲突。
- **新鲜度门禁**：解龄 > 2 个 MPC 周期（> 40.0 ms）即 `damped_hold`；QP 无解/超时同样走显式失败路径
  （移动中 `damped_hold`，急停 `torque_zero_release`）；不得降级为"继续跑旧解"（ADR-0009 §4.3）。

## 5. 判据（可测，事后不改）

① **通过** ⇔ 下列三条同时成立（≥2000 次连续求解、预热样本剔除后）：
1. 整步墙钟 **P99 ≤ 15.0 ms**（= 0.75 × 20.0 ms 预算）
2. 超时次数（整步墙钟 > 20.0 ms）= **0**
3. 稳态样本内 **max ≤ 20.0 ms**

现状：条件 1 成立（P99 14.102 ms = 70.51%）；**条件 2/3 未判** —— 200 次样本 max = 19.965 ms
= **99.825% × 20.0 ms**（= 95.832% × 20.8333），距越界 0.035 ms。

## 6. 必补测量（不改阈值与判据，只把口径包对）

1. **冷启动归属**：分离 CasADi 函数编译 / OSQP 工作区分配 / 对偶预热（`lam_a_prev`）等一次性开销
   （先预热约 20 次再计时），dump 最慢 10 个样本的 index。
   - max 落在前几次 ⇒ 条件 3 成立，且实现里预热必须放进 init 并记录启动序列；
   - max 落在稳态样本 ⇒ ① **不通过**，按 ADR-0009 收口。
2. **计时器包边界**：现脚本墙钟只包 `mpc.solve_QP`（`traj.generate_traj` 在 start 之前）。真实每拍
   计算量 = `generate_traj` + `solve_QP`。由现有数据反推该项：mean 差 = 11.893 − 10.078 = **1.815 ms**、
   P99 差 = 14.102 − 12.267 = **1.835 ms**，目前**未进预算**。补测：计时器包住整个 MPC 计算体
   （generate_traj + solve_QP + 时间戳打标），阈值不动，重出 P50/P95/P99/max。
3. **迁移性**：x86_64 结果只判"可继续"，不判"可上线"；① 的最终证据必须来自目标 aarch64
   （`casadi` / `pinocchio` 的 aarch64 wheel 已在 ADR-0009 §4.1 核实可下载），并在 BoardProfile 登记
   `casadi` / `osqp` / `numpy` 版本（本机 `mpc-env/` 同时存在 `numpy-1.26.4` 与 `numpy-2.2.6` 的 dist-info，
   `osqp 1.1.3`）。

## 7. ②③ 的前置（一并定死）

- **摩擦配对**：它 `src/convex_mpc/centroidal_mpc.py:15` `MU = 0.8`（摩擦锥），README L152 明确
  "改 centroidal_mpc.py 的摩擦系数时 MuJoCo 侧要同步改"；我们厂商
  `vendor/unitree_go2/unitree_robots/go2/go2.xml:8`（地板）与 `:33`（足端）均为 **0.4**，
  编译后 `build/scenes/handoff_lab/handoff_lab.xml:7-8`、`:31` 同为 0.4。
  ⇒ ②③ 的**达标判定只认同摩擦配对**（0.4/0.4、0.8/0.8）；交叉点（我们 0.4 / 它 0.8）只作灵敏度记录，
  不作达标依据。两侧数值必须从配置读出并写入报告，禁在脚本里改常量。
- **速度上界**：它 ex02 的指令是 0.8 m/s（`CMD_SCHEDULE` L46），我们 `max_speed_mps = 0.5`
  ⇒ 0.8 只能作为"它的参考工况"记录，**不得**作为 ② 的验收点；② 的验收指令速度 ≤ 0.5
  （安全策略不因对照而放宽），③ 按 `max_tilt_moving_deg = 15.0` 判。

## 8. 诚实边界

- 200 次求解的样本量不足以判 P99.9 / 尾部分布；条件 2/3 需 ≥2000 次连续样本。
- 本机实测用的是**它自带的 URDF**（经 Pinocchio），整机质量按 URDF 为 `15.019000000000002 kg`，
  与厂商 MJCF 的 `15.206408 kg` 差 **0.187408 kg** ⇒ 这是"它的模型"的时延，不是"我们模型"的时延。
- 为建动力学模型加了"不加载 mesh"适配层（`RobotWrapper.BuildFromURDF` 替换）；
  它默认要 ~35 MB 的 dae 网格。该适配只影响几何，不影响算法与被测 QP。
