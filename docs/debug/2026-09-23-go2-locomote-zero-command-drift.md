# locomote 路径「零指令漂移」分层实测：走路的真正前置条件（2026-09-23，A6a-④）

## 0. 触发与结论摘要

在排查「前进/后退跟踪只有指令的 16%、后退发散」时，我加了一个**诊断工况 `hold`**（指令
`(0,0,0)`、原地站 3 s）到 `scripts/verify_go2_locomote.py`。**结果推翻了「漂移是 walk 项造成的」
这一族假设**：

| 工况（全部 `vx=vy=wz=0`、3 s、100 Hz、同一段实现层代码） | 倾角峰值 | 偏航变化 | 净位移 | 平均 |
|---|---|---|---|---|
| 基线（MPC 力矩注入 1.0 + 支撑/摆动 PD 1.0 + 幅度 1.0） | 6.76° | −11.46° | **1.5189 m** | 0.506 m/s |
| 幅度斜坡改 1000 s（`amplitude_at(1 s)=0.001`，腿基本冻结在 home） | 5.34° | −22.51° | **1.6740 m** | 0.558 m/s |
| `weight_balance = 0`（**MPC 力矩完全不注入**，纯 PD + 步态相位） | 8.86° | +14.27° | **0.8250 m** | 0.275 m/s |
| **幅度冻结 ∧ `weight_balance = 0`（腿冻结 + 不注入力矩）＝控制组** | **0.08°** | **+0.00°** | **0.0070 m** | **0.002 m/s** |
| 支撑腿 PD 权重 0（支撑腿全走力矩级力控） | **80.28°**（翻倒） | −54.39° | 1.1118 m | 0.371 m/s |
| 摆动腿 PD 权重 0 | **172.30°**（翻倒） | −54.89° | 0.4487 m | 0.150 m/s |

**控制组（第 4 行）是这张表的关键**：腿冻结 + 不注入力矩时，机身**基本不动**（0.0070 m / 3 s、
倾角 0.08°、偏航 0.00°）⇒ 静止配置本身是平衡的，两个漂移来源由此被切成互不重叠的两半：

- **通道 A（MPC 力矩注入）**：腿冻结、无接触切换、无抬腿，单独注入力矩即漂 **1.6740 m / 3 s（0.558 m/s）**
  ⇒ 注入的力/力矩**本身**与机身水平运动不自洽，与「接触表切换」「摆动腿拖动」都无关（最先该修的一条）。
- **通道 B（PD + 抬腿/相位）**：不注入力矩、正常抬腿时漂 **0.8250 m / 3 s（0.275 m/s）**；
  腿一冻结就回到 0.0070 m ⇒ 本通道的漂移**由抬腿引入**。
- 两者叠加（基线）1.5189 m < 通道 A 单独的 1.6740 m ⇒ 存在部分抵消，说明它们不是简单相加。

（判据侧：`hold` 工况只判 `max_tilt_deg ≤ 15`，`vx=0`/`wz=0` ⇒ 速度与方向门禁按声明不适用；
上面五条**全部报 `SUCCEEDED` 但只有基线/幅度冻结两条在倾角上通过** —— 这本身也说明
「没有 failure 不等于走对了」，位移必须单独判。）

## 1. 三条可复核的结论

1. **零指令下机身就在漂 0.506 m/s**（1.5189 m / 3 s，方向 (−x, +y) 对角）。
   这个量级**比我们要的指令速度（0.2 m/s）大 2.5 倍** ⇒ 在此之前谈「跟踪精度」没有意义；
   这也解释了此前所有「前进指令跑成后退」的现象（4 s × 0.5 m/s ≈ 2 m 量级的漂移压过 0.8 m 的指令位移）。
2. **漂移与抬腿无关**：把幅度斜坡拉到 1000 s（腿几乎不动、`amplitude_at(1 s) = 0.001`），
   漂移**反而略增**到 1.6740 m ⇒ 「摆动腿 PD 拖动机身」这一族解释在 MPC 路径上**不成立**
   （它解释的是 wave/原地踏步那套的老现象；本条是**用实测把假设打掉**）。
3. **漂移至少有两个来源，都要修**：
   - MPC 力矩注入通道占 ~0.694 m（1.5189 − 0.8250，约 46%）；
   - 纯 PD + 步态相位通道自身仍有 **0.8250 m / 3 s = 0.275 m/s**（关掉力矩注入后剩下的那半）。

## 1.5 通道 A 的根因：QP 的零指令解**顶在摩擦锥角点上**（2026-09-23 追加）

诊断手段：给 `torque_hook` 的统计加了逐关节载荷向量 `last_payload_nm`、逐腿世界系力
`last_forces_n`、逐关节权重 `last_position_weight` 与 `joint_index_map`（只留最后一拍），
然后跑 **零指令 + 腿冻结（amplitude≈0）400 ms**（状态还接近 home，末拍即为静止解）：
`build/iraf-a6a6/hold-ampl0-400ms.json`。

末拍 QP 解（四腿世界系力，行序 `LEG_ORDER = FL/FR/RL/RR`，单位 N）：

    FL: ( +0.000,  +0.000,  -0.000)      ← 摆动腿（力 0，符合盒约束）
    FR: (+22.826, -22.826, +57.065)      ← 支撑腿
    RL: (+22.826, -22.826, +57.065)      ← 支撑腿
    RR: ( +0.000,  +0.000,  -0.000)

三个立刻能读出来的事实：
1. `mu × fz = 0.4 × 57.065 = 22.826 N` —— 两条支撑腿的切向分量 |fx| 与 |fy| **同时精确等于该值**
   ⇒ 解正压在**线性化摩擦锥的角点**上（`mu=0.4` 为声明值）。
2. 两条腿的切向力**同向**（都是 (+x, −y)）⇒ 水平分量不抵消：**净水平推力 (45.652, −45.652) N**，
   合模 64.6 N ≈ **0.30×mg**，方向 (+x, −y)；执行侧取 `−Jᵀf` ⇒ 机身被推向 **(−x, +y)**，
   与实测漂移方向（0.4 s 末 xy = (−0.0480, +0.0141) m）一致。
3. 末拍 Σfz = 114.13 N **< mg = 152.61 N** ⇒ QP 自己的模型认为竖直方向还欠 38 N。

单变量验证（`mpc_model.r_diag` 1.0e-5 → 1.0e-3，即把"几乎免费"的输入代价放大 100×；
其余一切不动）：`build/iraf-a6a6/hold-rdiag1e-3.json`

| 指标 | 生产档 `r_diag = 1.0e-5` | 诊断档 `1.0e-3` |

⇒ 输入代价近乎为零时，任何微小状态误差都会换来"几乎免费"的巨大输入，解被推到约束角点上；

    不注入力矩 + 正常抬腿（B 单独）      0.275 m/s

    基线（A + B）                       0.506 m/s（部分抵消）

## 1.6 A 通道的更深一层：`τ = −Jᵀf` 的**水平符号与竖直不自洽**（2026-09-23 追加，待证）

动机：A 通道的力（净水平 45.652 N）方向是 (+x, −y)，而机身漂移方向是 (−x, +y) —— 两者反向，
必须把「`τ = −Jᵀf` 到底在足端施加了什么方向的力」定死。

**已证（纯几何，无动力学）**：`_foot_jacobian` 自洽 —— 解析 J 与数值微分 `d(foot_pos)/d(q)`
逐元素对照 `max|解析−数值| = 1.324e-07`，列序 (hip, thigh, calf)、行序世界 (x,y,z) 都对得上
（探针 `build/iraf-a6a6/sign_axis_probe.py` A 段）。前右腿 J 的实测值：

    J(FR) = [ 0.000000  -0.264806  -0.132403 ]   ← x 行
            [ 0.264806   0.000000   0.000000 ]   ← y 行（髋关节只影响 y）
            [-0.095500   0.000000  -0.166849 ]   ← z 行

**已测（带支撑、逐轴双向、20 步 × 0.002 s）**：`build/iraf-a6a6/sign_axis_probe.py` B 段，
`τ = −Jᵀf`，四腿同值，机身质心速度增量（世界系）：

| 用例 | Δvx | Δvy | Δvz | 与 f 的关系 |
|---|---|---|---|---|
| f_x=+40 | **−0.29674** | +0.01444 | +0.50064 | **反号** |
| f_x=−40 | **+0.22911** | −0.10525 | +0.04311 | （同上，反向） |
| f_y=+40 | +0.00728 | **−0.21007** | +0.13639 | **反号** |
| f_y=−40 | +0.00622 | **+0.11707** | +0.27461 | （同上，反向） |
| f_z=+mg/4 | +0.00669 | −0.10811 | **+0.28020** | **同号**（撑住） |
| f_z=−mg/4 | −0.01700 | +0.05852 | **−0.10136** | （同上，反向） |

⇒ **竖直同号、水平反号**（x 与 y 都反）。注意同一 x 用例的 Δvz 相差很大（+0.50064 vs +0.04311），
说明响应里仍混着"关键帧未平衡、机身在下沉"的瞬态 ⇒ **本表只定符号，不定量级**。

**为什么这条最关键**：若水平注入被反号应用，那么 QP 的每一次水平修正都变成**放大**
（等效回路增益 ≈ 2）—— 这与本项目已经测到的全部现象自洽：

| 已测现象 | 反号假设下的解释 |
|---|---|
| 前进指令净位移只有 16% 且往复振荡 | QP 想推 +x，实际推 −x ⇒ 误差越大推得越猛 |
| 后退指令发散（Σfz 23.8×mg、摔倒） | 同上，正反馈 |
| `translation: measured` ⇒ 发散消失 | QP 水平参考取实测 ⇒ 水平指令力 ≈ 0 ⇒ 无放大 |
| `r_diag` ×100 ⇒ 漂移 1.5189 → 0.8081 m | 水平力变小 ⇒ 放大变小（残余 = B 通道） |
| 世界系锚定档 + `translation: command` ⇒ 1.08 m/s 失控 | 仍带水平指令力 ⇒ 仍被放大 |

**尚未证明**：直接量「接触反力 vs f」的探针 `build/iraf-a6a6/contact_force_probe.py` 本轮**没跑成**
（四足接触反力全为 0.000 ⇒ 该探针没读到接触，需修：先确认 `data.ncon`、"速度每步清零"下的
接触形成条件、以及 `mj_contactForce` 的 geom1/geom2 符号约定）。**在拿到接触反力之前，
「水平反号」只是由机身响应推出来的结论，不是直接测量** —— 下一轮第一件事就是把它变成直接测量。

## 1.7 结论：反号的原因找到了 —— `jacobians_now` 漏转置（2026-09-23 定案）

「水平反号」不是物理，是**接线缺陷**：

    `joint_torques(foot_forces, jacobian_transpose)` 契约要 **Jᵀ**（内部直接做 `M @ f`），
    而适配器 `jacobians_now()` 把 `_foot_jacobian(...)` 返回的 **J** 原样交出 ⇒ 实算 `J·f`。

数值（FR 腿，实测 J 值；解析 vs 数值微分 max|Δ| = 1.324e-07，J 本身没问题）：

    f=(40,0,0)：  J·f=(0,+10.5922,−3.8200)  vs Jᵀ·f=(0,−10.5922,−5.2961)   thigh 反号
    f=(0,40,0)：  J·f=(−10.5922,0,0)        vs Jᵀ·f=(+10.5922,0,0)         hip 反号
    f=(0,0,38.25)：J·f=(−5.0644,0,−6.3820)  vs Jᵀ·f=(−3.6529,0,−6.3820)     **同号**（calf 项完全相同）

⇒ **恰好只有水平反号**，竖直"看着正常" —— 与 §1.6 的机身响应实测完全一致。
为什么长期潜伏：此前所有单测/探针都用**单位矩阵**当雅可比（转置不改变结果）。

**修复与验证**（提交 2116210）：新增 `mpc.torque_provider.jacobian_transpose_from(J)` 作为唯一的
雅可比交付入口；`jacobians_now()` 经它交付。同一逐轴双向探针改走修复后入口：

    修复前：f_x=+40 ⇒ Δvx=−0.29674（反号）｜f_y=+40 ⇒ Δvy=−0.21007（反号）｜f_z ⇒ 同号
    修复后：f_x=+40 ⇒ Δvx=+0.29012｜f_y=+40 ⇒ Δvy=+0.21501（±完全对称）｜f_z ⇒ +0.35851
    ⇒ **三轴全部同号**，约定一致（不再是"竖直对、水平反"的分裂状态）

| backward vx=−0.2 | 误差 0.3458 | **误差 0.1029（稳态 ≈0.221 m/s，已逼近判据 0.10）** |

⇒ walk 项对前进有帮助（0.6826 → 0.3434），对后退**有害**（0.1029 → 0.3458）；
   而 **walk 关掉时后退几乎达标**（0.1029 vs 0.10），前进却只兑现 32% —— 说明残差不是"增益不足"
   这种对称量，而是**方向相关**的（步态自身的不对称 + 腿部几何前后差异 + 退让项在机身系里是
   对称给进而实际腿的伸展方向不对称）。
   ⇒ 下一步（判据同上）：先量零指令漂移的**方向与量级**（当前 hold 0.1131 m/3 s = 0.0377 m/s，
      方向未记），再决定是给退让项做方向相关声明，还是把「机身系对称给进」换成按腿/按方向的能力。

## 1.11 零指令漂移的归因：**100% 来自步态抬腿**（2026-09-23 晚，单变量）

同一生产档（`leg_position_gain_scale=0.3`、`stride_scale=1.0`），只改「幅度斜坡」把腿冻结
（`ramp_s: 1000` ⇒ `amplitude_at(3 s)=0.003`）：

| 档位 | 零指令 hold 净位移 | 平均速度 | 倾角峰值 | 偏航变化 |
|---|---|---|---|---|
| 抬腿（`amplitude = 1`） | 0.1131 m | −0.0377 m/s（纯 −x） | 3.53° | +0.39° |
| **腿冻结（`amplitude ≈ 0.003`）** | **0.0036 m** | +0.0012 m/s | **0.18°** | +0.01° |

⇒ **差 31 倍**；冻结档等于"站着不动"（3 s 走 3.6 mm）⇒ 零指令漂移**全部由步态的摆动/支撑目标
（`foot_offset` 的抬腿形状 + 支撑腿目标恒定）产生**，与 plant 的接触/摩擦偏置无关
（§1.10 的 9% 开环不对称不足以解释 0.038 m/s 的稳定漂移）。

**这条把前后方向的不对称也解释通了**：步态自身给机身一个**单向 −x（向后）推**（0.038 m/s），
⇒ 它对**前进指令是阻力**（所以前进需要更大步幅补偿，stride≈2.05）、对**后退指令是助力**
（所以后退在 stride 1.0 就超调 k₀=1.11、stride 0.15~0.2 才合适）。机制：摆动腿在空中被目标
向前带（机身系里 dx 变化）时，位置环的反作用把机身往**后**推；而支撑腿目标是恒定的（`dx ≡ 0`）
⇒ 没有任何前向反作用与之抵消 ⇒ 净向后漂。这正是 2026-09-23-gait-drift 里 wave 档 0.494 m/s
漂移的同一机制，只是现在 trot + 三处修复 + gain 0.3 下已降到 **0.038 m/s（13× 更小）**。

⇒ **正确的下一步不是继续放大步幅补偿，而是在源头消掉这个单向推**：
   候选顺序（都要单变量 + 判据）：
   1. 支撑腿目标的**反向给进**在零指令下是否也给（当前零指令 ⇒ 退让项精确 0 ⇒ 支撑腿零反作用）；
      若给支撑腿一个与摆动反作用匹配的零指令前向给进，则漂移可在此消掉，且不影响指令跟踪；
   2. 摆动轨迹的**反作用补偿**（对称化摆动相在机身系的净冲量）；
   3. 若 1/2 都不行，才考虑方向相关步幅（标定，须在文档里写明是标定）。

### 1.11.1 已排除的两条（同一 hold 工况，单变量）

1. **不是「机身系目标 vs 世界系锚定」的差别**：`gait.walk.anchor = measured_pose`（世界系钉住足端、
   实测位姿换算）时 hold 净位移 **0.1648 m**、倾角 4.52°，比 `command_ramp` 的 0.1131 m / 3.53° **更差**
   （1.46×）⇒ 锚定档不能消掉漂移（与 §1.10 里它在跟踪上更差一致）。
2. **不是摆动腿"前带"**：读了实现才知道 `foot_offset` 的摆动形状是 `(dx ≡ 0, dz = height·sin/cos)`
   —— **只有竖直抬放、没有前后摆**。⇒ 单向 −x 推只能来自「抬放（竖直）+ 支撑交替 + 机身俯仰/滚转」
   的**整流效应**（机身姿态振荡 × 支撑腿把构型钉在机身系 ⇒ 每周期留下一点净冲量）。
   ⇒ 要定死它需要按周期对齐的**逐腿接触力时程 + 机身俯仰/滚转相位**（下一轮的第一步）。

## 2. 顺带钉住的两个事实（都曾被我误判过）

- **支撑腿位置权重不能压到 0**：`stance_position_weight = 0` ⇒ 倾角 80.28° 翻倒。
  机制：B1 的 `position_weight` 会**把 τ_pd 里的重力前馈一起乘 0**（`unitree_go2.py` 注释原文：
  「τ_pd 含重力前馈一并乘 0」）⇒ 换来的不是「纯力控」，而是「连重力补偿都没了」。
  ⇒ 「MPC 力矩通道单独撑住机身」**已被实测否证**（MPC 路径的力矩不足以代替重力/构型支撑）。
- **声明门禁在挡这个坑**：`w_bal = 0` 与 `balance.stance_weight_position = 0` 同时出现时，
  装配期直接显式失败（实测报错原文：`balance.stance_weight_position 与 balance.weight_balance
  不得同时为 0（… 两者同时为 0 时支撑腿控制量恒为零，整机将直接塌陷）`）。
  我第一次试 `w_bal=0` 就是被这条门禁拦下的 —— 门禁有效。

## 3. 修正后的优先级（这决定了下一轮做什么）

原先的队列（先做笛卡尔足端阻抗 + 期望机身轨迹前馈）**前提不成立**：如果零指令就漂 0.5 m/s，
再好的足端轨迹也会被这个漂移吃掉。⇒ 新队列：

1. **先定位并消掉零指令漂移**（两个来源分别处理）：
   - 来源 A（纯 PD + 步态相位，0.275 m/s）：逐项查 PD 通道里与机身水平运动耦合的项
     （`stance_clearance_m`、`foothold`、`position_offset`、四个髋关节的 PD 目标与实测几何的一致性）；
     判据：`hold` 3 s 净位移 ≤ 声明阈值（先记录实测，再按数据定阈）。
   - 来源 B（MPC 力矩注入，~0.23 m/s）：核对 `f_world → τ = −Jᵀf` 的框架/映射/接触表一致性
     （世界系雅可比 vs 机身系、`index_map` 到 Profile 关节序、QP 接触表与实测接触的一致性）。
     抓手：零指令下把注入的 Σf 与实测合力矩做时程对照（应当相互抵消而不是产生净推力）。
2. 漂移进入判据范围后，再回到四工况（含首次左转/右转）与 walk 项的取舍。
3. 笛卡尔足端阻抗 + 期望机身轨迹前馈**推后**：它是「走得好」的手段，不是「不漂」的前提。
