## 1. 本轮修掉的两条真缺陷

### 1.1 MCP 入口的工作目录语义没对齐 systemd 单元（阻断级）

AgentOS 以 stdio 拉起 `python3 -m iraf_adapters.mcp.server` 时，进程 cwd 不是版本目录；
而装配单（`/etc/iraf/edge-intel.env`）里的 `IRAF_PROFILE=profiles/piper_mujoco.yaml`、
`IRAF_SKILL_ROOT=<version>/skills` 都是**相对**路径 ⇒ 实测返回：

```
Error executing tool iraf_submit_task: [Errno 2] No such file or directory: 'profiles/piper_mujoco.yaml'
```

单元模板用 `WorkingDirectory=/opt/iraf-sdk/current` 表达同一事实，MCP 入口没有复现它。
修复：`src/iraf_adapters/mcp/server.py` 增加 `_enter_version_dir()`（import 期 `os.chdir`
到 `IRAF_VERSION_DIR`，默认 `/opt/iraf-sdk/current`）。
回归：`tests/unit/test_mcp_server_layer.py::test_chdir_to_version_dir`（AST 静态检查，
与本文件其余用例同风格，不需要安装 `mcp`）。

### 1.2 探针写死了板上不存在的路径

`scripts/probe_mcp_client.py` 原先固定 `/opt/iraf-extras/iraf_mcp_server.py`（随包交付后
板上没有该文件）。改为与登记一致的 `-m iraf_adapters.mcp.server`，保留
`IRAF_MCP_SERVER=<路径>` 兼容旧登记。

版本 0.3.0 → **0.3.1**（版本单一来源：`pyproject.toml#project.version`）。

## 3. 平台级：三条通道的实测结论（1.0.0）

| 通道 | 是否触发 MCP 发现 | 实测结果 |
|---|---|---|
| `intewell-agent-cli -z`（单轮） | 是（但后台线程） | 「无」——工具要**下一轮**才被采纳，单轮结构上看不到 |
| `intewell-agent-cli acp`（多轮 stdio JSON-RPC） | **否** | 第 2 轮模型原话：「我的工具集里没有 `iraf_submit_task` 这个工具」 |
| dashboard 9119（`/api/ws`，tui_gateway） | 启动时后台发现 | 机制上正确，但**尚未程序化复验**（见 §4） |

代码依据（读包确认，不是猜）：

- `agentos/capabilities.py:79-85`：`background_mcp=True` ⇒ 起后台线程并立刻返回
  `mcp_discovery_pending=True`；docstring 原文：工具由 `agent/turn_context.py`
  在 the next turn 采纳。
- `intewell_cli/main.py:12373`（dashboard 启动路径）：注释写明 desktop 会话走
  `tui_gateway.server._make_agent`，「this path only snapshots the tool registry — it never
  starts MCP discovery」，所以这里**补**了 `start_background_mcp_discovery(thread_name="dashboard-mcp-discovery")`。
- `intewell_cli/main.py:12665-12680`：`_command_has_dedicated_mcp_startup` 把 ACP 归入
  「自己后面会做」的入口，但 `acp_adapter/` 里**没有**调用 `start_background_mcp_discovery`
  （`grep -rn start_background_mcp_discovery` 只命中 main.py / mcp_startup.py / tui_gateway）。
  ⇒ ACP 会话天生看不到 MCP 工具，这是 AgentOS 侧缺口，不是我们的绑定错。

## 4. 未闭合：dashboard 的程序化复验

dashboard 只认表单登录：`POST /auth/password-login`（+ session cookie），
`POST /api/auth/ws-ticket` 需要登录态；`curl -u admin:123` 实测 **401**
（`/api/sessions` 401、`/api/auth/ws-ticket` 401、`/` 302）。
`internal_ws_credential()` 是**进程内**凭据（只通过环境变量发给它自己 spawn 的 PTY 子进程），
外部拿不到。所以自动化复验需要一个能登录的 admin 口令。
另外注意时序：MCP 是 06:55 登记的，而 dashboard 进程 05:54 就起来了 —— 即便它启动时做了
发现，看到的也是**登记前**的配置；复验前需要重启 dashboard 或确认它按会话重建 agent 时会再发现。

## 6. dashboard /chat 的真实执行位置：worker 容器（2026-10-21 追加）

用户报 `/chat` 里模型回答"没有 iraf_submit_task"，核实后发现**不是模型幻觉**，是三层缺口：

1. **dashboard 的对话跑在容器里**：`agentos-worker-1/-2`（镜像 `agentos-worker:b7fd7828-arm64`）
   的 home 是 `/home/agentos/.intewell`，与宿主 `/root/.intewell` 完全两套。
   我们在宿主登记的 `mcp_servers.iraf-task` 容器里根本看不到。
2. **worker 镜像里没有 `mcp` 这个 python 包**（只有 `agentos` / `tools`）⇒ 容器内的 AgentOS
   连"能当 MCP 客户端"都不成立：`mcp add --url` 直接崩在
   `RuntimeError: Event loop is closed`（tools/mcp_tool.py:2161）。
3. 因此模型在容器里 `skills_list` 空、全盘搜 `iraf` 零命中，只能诚实回答"拿不到"。

处置（容器内，实测生效）：

```bash
docker exec agentos-worker-1 /usr/local/bin/python3.11 -m pip install --no-cache-dir \
  -i https://mirrors.aliyun.com/pypi/simple/ "mcp==1.26.0"      # 与宿主同版本
# 注意：先装成 2.3.0 会用到 mcp.client.streamable_http.streamablehttp_client（该 API 已移除），
#       AgentOS 1.0.0 期望 1.x，必须钉 1.26.0。
docker exec -i -u agentos -e HOME=/home/agentos agentos-worker-1 \
  sh -c "cat > /home/agentos/.intewell/config.yaml" <<'YAML'
mcp_servers:
  iraf-remote:
    url: http://10.203.247.147:8765/mcp
    enabled: true
YAML
docker restart agentos-worker-1 agentos-worker-2
```

重启后两个容器内直连自检（HTTP，不依赖容器里装 IRAF）：

```
TOOLS ['iraf_submit_task', 'iraf_get_task']
```

**未闭合**：容器内的 `mcp` 包与 `config.yaml` 都在容器文件系统里，容器被重建即丢 ⇒
必须由厂商把 `mcp` 打进 worker 镜像，或改用声明下发（AgentOS 的 declarations 通道）。
另外 worker 镜像与宿主版本必须对齐（1.26.0），版本漂移会静默断链。

**概念边界（这次混淆的根）**：历史会话里出现过平台侧 skill `iraf-mcp-task-submit`，
它用 `host_command` 跑脚本、在 shell 里再拉起我们的 stdio MCP。那既不是机器人 Skill，
也不是任务级 MCP 工具，而是一条**旁路**——正是"AgentOS 的 skill 与 IRAF 的 skill 混了"
的实体。宿主 `~/.intewell/skills` 现已为空（curator 07:08 清过）。口径重申：
平台侧唯一正确入口是两个任务级 MCP 工具；机器人 Skill 只能由 IRAF Skill Manager 选，
禁止用平台 skill 去包一层调 MCP。
