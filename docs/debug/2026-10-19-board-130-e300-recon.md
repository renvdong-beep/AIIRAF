## 4. 同机双角色的路径隔离（本次改动）

`deploy/sdk/lib_install.py` 把安装记录写成 `<prefix>/<version>/<file_record>`，而 `file_record`
取自 `effective["file_record"]`、**不含角色 id**（第 181/207 行）⇒ 两角色共用 `/opt/iraf-sdk`
会互相覆盖同一个记录文件，卸载会删错文件。故在 `config/install/install_profiles.yaml` 给
`edge-motion` 做了角色级路径覆盖：

```
prefix     /opt/iraf-sdk-motion
config_dir /etc/iraf-motion
log_dir    /var/log/iraf-motion
data_dir   /var/lib/iraf-motion
```

校验：`scripts/install_profile_check.py --profile edge-motion` → 90 项检查 0 未通过；
`pytest tests/unit/test_install_profiles.py` → 17 passed。

## 6. 独立复核发现并修复的真缺陷：env 文件里的 JSON 被剥掉双引号

`--list-skills` 首次运行直接崩：
```
json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
```
根因：模板行 `IRAF_BACKEND_CONFIG={"endpoint":…}` 未加外层引号；该文件既被 shell `source`
也被 systemd `EnvironmentFile=` 解析，**两者都会剥掉双引号** ⇒ 值变成 `{endpoint:10.203…}`。
用自检脚本对照实测：

```
A) 正确写法（单引号包 JSON）→ 列出 13 个技能，exit 0：
   accept_payload / calibrate_camera_to_base / calibrate_grasp / display_pick / dock_for_handoff /
   engineering.robot_adapter / locomote / move_joint / pick_object / place_object / stand / stop /
   visual_pick
B) source /etc/iraf/edge-intel.env（修前）→ JSONDecodeError（见上）
   修后同一命令 → 正常列出技能
```

修复：
1. `deploy/sdk/env/edge-intel.env.tmpl` 改为 `IRAF_BACKEND_CONFIG='{…}'`（附注释说明原因）；
2. 板上 `/etc/iraf/edge-intel.env` 就地修（备份 `edge-intel.env.bak.quote-fix`），复验 source 后可用。
