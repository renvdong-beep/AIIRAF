# E300 智控域（.147）装 IRAF SDK 0.3.10 → 0.3.11（2026-10-22）

范围：**只升板上的 IRAF SDK**，不碰 AgentOS（平台侧配置/容器一律未动）。
机器：智控域 10.203.247.147（Intewell V1.2.1 / aarch64 / py3.11.6 / glibc 2.38 / kernel 6.6.10）。

## 1. 为什么最后装的是 0.3.11（不是 0.3.10）

0.3.10 装成功后跑 `board_diag.sh`，`--list-skills` 自检直接崩：

```
FileNotFoundError: [Errno 2] No such file or directory: 'profiles/piper_mujoco.yaml'
  iraf_adapters/bootstrap.py:15 → iraf_core/profile.py:162
```

装配单里 `IRAF_PROFILE=profiles/piper_mujoco.yaml` 是**相对路径**，而 CLI 的 cwd 不是版本目录。
systemd 单元靠 `WorkingDirectory=` 兜住，CLI/MCP/探针各有各的 cwd ⇒ 同一份装配单在不同入口
静默分叉（与 2026-10-21 的 MCP cwd 缺陷同源，这是第二处）。

修法（0.3.11，纯我方）：`iraf_adapters/bootstrap.py` 新增 `resolve_path()` —— 相对路径按
`IRAF_VERSION_DIR`（默认 `/opt/iraf-sdk/current`）解析；解析不到就**原样返回**，让下游报出装配单
原始值（不伪造、不吞错）。`build_runtime_from_env()` 对 PROFILE / SAFETY_POLICY / SKILL_ROOT /
EVENT_STORE 四处都走它（一次修好 CLI 与 MCP 两条入口）。
回归：`tests/unit/test_bootstrap_paths.py`（6 条，含 AST 防回潮）。

修完复验：错误从"文件找不到"前移为"token 缺失"⇒ 路径解析生效（profile/safety/skills 均已加载）。

     `IRAF_PROVIDER_TOKEN`）。装配单按设计**不写凭据**，systemd 单元也只有 EnvironmentFile ⇒
     **板上没有 provider token 的注入机制**，这是既有缺口，不是本次回归。

## 5. 0.3.12 → 0.3.13：凭据注入与 diag 判据（同日续）

0.3.11 装完 board_diag 三项红同因 `ValueError: token`。根因不是代码 bug，是**凭据没有受控来源**：
装配单按设计不写凭据，systemd 也没有注入点，而 CLI/探针不走 systemd。

处置（纯我方）：

| 版本 | 改动 |
|---|---|
| 0.3.12 | `--secrets-file` 落地 `<config_dir>/provider.token`（600）+ unit 加 `EnvironmentFile`；`RemoteProviderBackend` 支持 `token_file` 兜底 |
| 0.3.13 | 第一版只落 `IRAF_PROVIDER_TOKEN`，单元立刻 `exit 2: IRAF_GRPC_TOKEN must be provided by deployment` ⇒ 改为**多键** `runtime.secrets`（白名单 `IRAF_PROVIDER_TOKEN / IRAF_GRPC_TOKEN / IRAF_AGENTOS_TOKEN`），安装器校验键名、600 权限失败即中止 |

diag 判据修正（0.3.13 同步）：edge-* 角色的 gRPC 单元**只装不启**是设计
（`IRAF_GRPC_DEVELOPMENT=true` + 仅 loopback + `simulation=true` 才允许起），
原判据把"未启用"当缺陷 ⇒ 改成三态：enabled 必须 active；disabled 记 ○（不判红）。

实测（.147，0.3.13）：

```

/etc/iraf/runtime.secrets    600，265 字节（含注释行）
CLI --list-skills            12 个技能可列（accept_payload / pick_object / place_object / stop …）

board_diag                   IRAF 就绪=True；唯一 ○ 是"IRAF 进程存在"（设计只装不启）
```

**未闭合（诚实标注）**：板上的 `runtime.secrets` 目前是 **SELFTEST 占位值**（两个键都是
`selftest-...`），只够让 CLI 自检与只读盘点通过；任何真实执行都会因 Provider 鉴权失败
fail-closed（不会伪造成功）。真实凭据（`IRAF_PROVIDER_TOKEN` 必须与 x86 Provider 一致、
`IRAF_GRPC_TOKEN` 与调用方一致）需由掌握方提供后重装/替换。

另：若曾手工启停过旧单元，重装后 `systemctl` 会提示 unit changed on disk —— 常规流程
（先受控卸载再装，单元不重名冲突）不需要 `daemon-reload`；本次是手工启停造成的边缘态。

口径：**simulation=true**，不构成真机能力证据（AGENTS §0.1 / 1.7）。
