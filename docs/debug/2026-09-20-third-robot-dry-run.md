## 3. 干跑发现的两个真实问题

### 3.1 求解器写死"法兰 x 轴 = 开合轴"（已修）

demo3 的手指沿法兰 **y** 轴分离，而求解器假定开合轴 = 法兰 x 轴 →
姿态约束永远无法满足：

```
ValueError: 参考姿态未满足姿态约束: 夹爪指向偏差=20.648 deg 开合轴偏差=86.536 deg
```

修法：**从模型实测局部轴**构造目标旋转，而不是再写一套约定 ——
在种子位形下量出"法兰→夹持区中点"与"左指→右指"在法兰局部系中的方向
（`v_point_local` / `v_spread_local`），再把局部基映射到期望的世界方向：

```
R_target = W · Lᵀ,  L = [v_spread_local, v_point_local×v_spread_local, v_point_local]
                    W = [spread_world,   pointing_world×spread_world,   pointing_world]
```

自证：`R·Rᵀ = I`；实测局部轴不垂直即显式失败。

**关键回归证据**：改完后 UR5e 的参考姿态与改动前**逐位相同**
（0 处差异 > 1e-9，关节角完全一致，姿态偏差仍为 0.006467°）——
因为该机型恰好符合旧约定；也就是说这个改动对现有两台机型是"零影响"，只对
"不符合旧约定"的新机型解锁能力。

### 3.2 声明必须与运动学自洽（门禁正确拒绝）

demo3 是平面臂：当工具被要求竖直朝下时，末端的俯仰和被锁死，位置只剩
一条一维可达曲线。把目标放在台面高度（z=0.025）就要求肘部折到接近自撞的
位置，且实测夹持区中心与目标差 7.8~16.6mm；求解器在不可达时会**发散到关节限位**
（实测 q1/q2/q3 全部顶到限位、残差 507mm、姿态偏差 117°）。

门禁给出的拒绝是准确且可定位的：

```
ValueError: 夹持区中心与抓取目标不一致: |measured - target|=0.008441 m
```

这正是这些门禁存在的意义：**它不会把一个"看起来收敛"的坏解写成通过**。
干跑在此止步，属于预期行为而非框架缺陷 —— 要跑通需要把目标放到实测可达集内，
或改用带腕部俯仰且工作空间覆盖台面的构型（demo3 已加 q4，但目标仍在可达集外）。

## 4. 干跑证明了什么、没证明什么

证明：
- **接入不需要写代码**：一台全新命名的 4 自由度臂能被
  `profile_check` / `build_baseline` 按配置识别并推进到运动学求解阶段；
- **机型差异只在声明里**：关节名、指腹 geom、夹持区、工具指向、开合轴、
  后退方向、种子、限位、验收阈值、光源、相机全部来自配置；
- **门禁是真的在守**：不自洽的声明会被显式拒绝，不会产出"看起来成功"的场景；
- **改动可回归**：新机型暴露的假设被修掉后，既有两台机型数值逐位不变。

没有证明（仍是诚实缺口）：
- demo3 尚未跑到抓取验收（需要先把目标放到可达集内）；
- 抓取验收还依赖"夹爪几何 + 摩擦 + 力阈值"这类物理合理性，声明正确不等于能抓住。
