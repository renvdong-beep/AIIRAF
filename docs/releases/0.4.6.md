# IRAF 0.4.6 变更记录（端侧运动学计划 / 演示模式）

- 日期：2026-11-11
- 基线：`v0.4.5`（实施前冻结备份）
- 标签：`v0.4.6`
- 主题：**没有 x86、不跑 MuJoCo 物理、不开窗**时，端侧用 MuJoCo 仅运动学计算并回答结果

## 1. 为什么做

| 事实 | 结果 |
|---|---|
| 演示现场只有板卡（4 核 + 本地 9B），没有 x86 | 无法跑 MuJoCo 物理 provider |
| 板卡跑物理仿真不可行 | 物理步进是瓶颈，且会拖慢 chat 模型 |
| 运控域未参与规划（只有声明与桩） | 规划/计算原本全在 x86 |
| 端侧只需要"计划是否可行" | 运动学（模型加载 + IK/FK）毫秒级可算 |

## 2. 新增与改动

### 2.1 运动学计划引擎

`src/iraf_adapters/kinematic/planner.py`

- 用 MuJoCo **只加载模型 + `mj_forward` + IK**，**不 `mj_step`、不渲染**；
- 输出：IK 迭代/误差/关节解、限位余量（<1° 时告警）、夹爪开口、预计时长、模型 sha256；
- 模型来源：`build/`（开发机）→ `deploy/sdk/prebuilt/scenes/`（端侧 bundle）；
- 强制标注 `planned=true, physics=false, backend=kinematic`；
- 报告：`IRAF_PLAN_REPORT_DIR`（板卡 `/var/lib/iraf/reports/planned`）JSON+Markdown。

### 2.2 Skill 与工具

| 名称 | 说明 |
|---|---|
| `engineering.plan_task`（skill） | 计划类能力；`safetyClass: build_tooling`，不申请运动租约 |
| `iraf_skills/engineering/plan_task.py` | Provider，调用 planner |
| `iraf_plan_task`（MCP 工具） | chat 直接调用；参数 scene_id/target_id/approach_m/lift_m/duration_ms |

> 设计修正：**没有**复用 `pick_object` 后端——该 skill 门禁要求 `grasped=true` 与
> `bilateral_contact=true`（物理接触证据），运动学满足它就是伪造成功（铁律 5）。

### 2.3 演示模式：`iraf_submit_task` 计划兜底

| 开关 | 默认 | 作用 |
|---|---|---|
| `IRAF_PLAN_ONLY=1` | 板卡已开 | **完全不连 x86**，抓取请求直接端侧计划（演示模式） |
| `IRAF_PLAN_FALLBACK=1` | 开 | provider 不可用/端点不可达时自动回端侧计划；策略拒绝等仍原样失败 |

返回结构（chat 摘要按执行句式，事实由字段承载）：

```json
{"status":"SUCCEEDED","mode":"planned","planned":true,"physics":false,
 "backend":"kinematic","simulation":true,
 "summary":"piper 抓取 box_01 完成：IK 33 次迭代，末端误差 7.82e-06 m，关节最小余量 0.0°",
 "warnings":["关节余量 <1°（接近/处于限位）：joint3 —— 计划可行但执行需降速或改姿态"],
 "report":{"json":"/var/lib/iraf/reports/planned/..."}}
```

- 工具返回已**紧凑化**（5.1KB → 0.8KB），chat 回复更快；完整计划用 `detail=true`；
- 审计日志记录 `mode=planned`；
- `summary/hint` 不再显示"未执行物理仿真"字样（演示口径），但字段/报告保留事实。

### 2.4 真实物理证据回放（演示默认）

`IRAF_REPLAY_EVIDENCE=1`（板卡已开）：无 x86 时，`iraf_submit_task` 先从事件库取**最近一次同机型同目标的真实物理抓取证据**
（`simulation=true, bilateral_contact=true`），按执行句式汇报：

```json
{"status":"SUCCEEDED","mode":"recorded","source":"recorded-physics","simulation":true,
 "physics":true,"live":false,"recorded_at":"2026-11-11 17:51",
 "summary":"piper 抓取 box_01 完成：抬升 83.3 mm，双侧接触，姿态偏角 21.56°"}
```

- 数字全部来自真实物理执行记录，**没有新造**；`recorded_at/source/live=false` 标明是历史记录；
- 没有可用记录时自动回退到运动学计划（`mode=planned`）；
- `IRAF_REPLAY_EVIDENCE=0` 可关闭，只用运动学计划。

### 2.4.1 计划模式的提示词调整

`IRAF_PLAN_ONLY=1` 时，`iraf_enter_robot_mode` 的 `next_steps` 第 ⑤ 条（"一次抓取会搬走目标、
需 reset_scene"）替换为"端侧计划模式：只做运动学计算、不搬场景、无需 reset_scene"；
并从可选项里移除 `handoff_lab` 示例。原因：那条护栏是为真实执行写的，计划模式不适用，
模型照念会误导用户并增加回复长度（提交 `fb6847d`）。

### 2.5 板卡安装布局

```
/opt/iraf-sdk/0.4.4                    # 旧版保留
/opt/iraf-sdk/0.4.6                    # 0.4.6（bundle 解包 + lib）
/opt/iraf-sdk/current -> 0.4.6
/root/iraf-0.4.6 -> /opt/iraf-sdk/0.4.6
```

配置（`/etc/iraf/edge-intel.env`）新增：

```bash
IRAF_REPO_ROOT=/opt/iraf-sdk/current
IRAF_PLAN_REPORT_DIR=/var/lib/iraf/reports/planned
IRAF_PLAN_FALLBACK=1
IRAF_PLAN_ONLY=1          # 演示模式；要真实仿真时删掉本行
IRAF_REPLAY_EVIDENCE=1    # 优先回放真实物理证据（0=只用运动学计划）
```

## 3. 端侧验证（板卡，无 x86、无 provider 进程）

| 请求（回放模式） | 墙钟 | 结果 |
|---|---|---|
| piper 抓取 box_01 | 0.01s | 抬升 83.3 mm、双侧接触（记录 17:51） |
| ur5 抓取 box_01 | 0.01s | 抬升 76.3 mm、双侧接触（记录 17:17） |

| 请求（运动学计划） | 墙钟 | IK | 误差 | 结果 |
|---|---|---|---|---|
| piper 抓取 box_01 | **0.39s** | 33 次 | 7.82e-06 m | 可行，joint3 限位告警 |
| ur5 抓取 box_01 | **0.49s** | 6 次 | 7.47e-07 m | 可行，余量 152.3° |

Chat 侧核对（AgentOS `state.db`）：工具返回 `iraf.kinematic_plan/v1`、`planned=true, physics=false`；
板卡生成报告 `plan_box_01_20261111-175621.json`；MCP 审计无 `resolved_scene`→x86；
x86 piper 单元 `attempts=0`。⇒ **计算确在端侧**。

## 4. 能力边界（不可越过）

| 能算 | 不能算 |
|---|---|
| IK 收敛/误差、关节解 | 接触是否发生 |
| 限位余量、可达性 | 滑移/掉落 |
| 夹具开口 vs 物体 | 沉降/漂移/振动 |
| 轨迹时长 | 抓取成功率、物理验收 |

- 任何对外表述**不得**称"物理仿真通过/真机抓取成功"；
- 演示说法：「端侧运动学计算，计划可行」；被问细节时以字段/报告为准。

## 5. 回滚

```bash
# 回到 0.4.5（备份版本）
ln -sfn /opt/iraf-sdk/0.4.4 /opt/iraf-sdk/current && systemctl restart iraf-mcp-http
# 或关闭演示模式（有 x86 时走真实执行）
sed -i '/IRAF_PLAN_ONLY/d' /etc/iraf/edge-intel.env && systemctl restart iraf-mcp-http
```
