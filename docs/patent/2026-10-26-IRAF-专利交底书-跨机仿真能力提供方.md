## 一、技术领域

本发明属于机器人控制与软件架构交叉领域，具体涉及一种将机器人任务编排/技能执行/策略放行
（下称"控制面"）与真实物理能力实施（下称"执行面"）在**进程与主机两个维度上分离**，
并保证跨机调用后"单写者、可追溯、失败关闭、仿真与真机同源"的机器人能力调用方法及系统。
适用对象：具备多机型、多板级、需要"开发机仿真验证 + 目标端真实执行"的机器人应用框架与平台。

## 二、背景技术

### 2.1 现有技术格局

| 路线 | 解决什么 | 不解决什么 |
|---|---|---|
| 厂商官方机器人栈（本体厂 SDK + 官方示例） | 单一机型的底层运动与感知 | 跨机型/跨板级的统一任务与技能层；无仿真-真机同源判据 |
| 通用机器人中间件（消息/动作总线，如 ROS 2 类系统） | 进程间通信与远程调用范式 | 远程调用后的执行约束（单写者、围栏令牌、终态不可复活）不随之成立 |
| 机器人技能编排框架 | 任务分解与技能组合 | 技能执行落点固定在本机；把仿真写进框架分支导致判据漂移 |
| 通用智能体平台 / 大模型编排 | 语义理解与工具调用 | 允许模型绕过技能与策略层直接下发执行；无执行域租约概念 |
| 仿真-真机迁移（sim-to-real）研究栈 | 策略迁移与建模差异 | 关注策略精度，不关注"调用链的可追溯与约束在跨机后是否仍成立" |
| 机器人车队/远程运维系统 | 多机调度与远程监控 | 面向运维而非实时动作语义；无单调令牌与幂等执行标识的成套约束 |

### 2.2 现有技术的具体缺陷

| 编号 | 缺陷 | 后果（现场可观察现象） |
|---|---|---|
| D1 | 仿真引擎与框架同处一台目标端机器 | 目标端（边缘板卡）缺少仿真依赖或资源不足；或为装仿真而破坏认证基线 |
| D2 | 为开发机另写一套"仿真版"框架 | 任务判据与真机链路不同源，仿真通过不能提示真机风险；同一任务两侧给出不同结论 |
| D3 | 跨机调用只做"远程过程调用" | 远程端成为黑盒：谁生成执行标识、谁持有资源、旧请求是否生效均无保证；并发调用互相踩踏 |
| D4 | 资源占用按"连接/会话"持有 | 会话断开即泄漏，或反之长期占用导致"复位 → 立刻动作"必报资源占用；占用无单调递增令牌 |
| D5 | 执行面能力清单由控制面配置而非自报 | 声明与实现不一致（如声明 3 项实际 6 项），策略层按错误清单放行或误拒 |
| D6 | 仿真结果与真机结果不带来源标识 | 仿真结论被表述为真实能力，事故归因错误 |
| D7 | 失败路径只给"失败"一个码 | 截止时间缺失、令牌回退、终态复用、资源占用无法区分，现场无法定位 |

> 收敛成一个技术问题：**当机器人能力实施者从"本机进程"变成"网络对端、可能延迟/失败/僵尸、
> 且可能只是仿真替身"时，如何保证物理动作的控制仍满足"同一执行器单写者、动作可追溯、
> 旧请求不生效、失败显式且可归因、仿真结论不被冒充为真机能力"这五条约束。**

## 三、发明内容

### 3.1 发明目的

1. 使执行能力可在**执行面之间替换**（本机 / 跨机 / 仿真替身），而任务编排与判据保持同源。
2. 使跨机调用仍满足单写者：同一资源任一时刻仅一个活动执行域租约。
3. 使"复位 → 立刻动作"这类连续操作不被上一动作的残留占用阻塞。
4. 使执行标识、围栏令牌、终态三者构成不可绕过的追溯与拒发机制。
5. 使执行面自报能力并带仿真标识，装配期可机器核对声明与实现。
6. 使各类拒绝彼此可区分（截止时间/终态复用/令牌回退/资源占用/能力未声明）。

### 3.2 技术方案总述

```
   ┌──────────── 控制面（边缘运行面：任务编排 / 技能执行 / 策略放行） ─────────────┐
   │  任务语义 → 任务编排 → 技能选择与参数校验 → 策略放行 → 执行请求(含 deadline) │
   └───────────────────────────────┬──────────────────────────────────────────────┘
                                   │ 版本化接口（截止时间 · 取消 · 幂等键 · 凭据）
        ┌──────────────────────────┴───────────────────────────┐
        ▼                                                      ▼
 ┌─ 执行面 A：本机/实时域 ─┐                        ┌─ 执行面 B：仿真替身（x86）─┐
 │ 校验→租约→令牌→执行    │  ← 同一套校验与约束 →   │ 校验→租约→令牌→执行        │
 │ 能力：驱动/现场总线    │                        │ 能力：物理仿真 + 图形显示  │
 └──────────┬─────────────┘                        └───────────┬───────────────┘
            │ 实测事实（接触/间隙/速度/时间戳/仿真标志）        │
            └──────────────────┬──────────────────────────────┘
                               ▼
                  权威执行事实记录（状态 / 令牌 / 终态 / 拒绝码）
```

图中"同一套校验与约束"是本发明与传统远程调用的分界：**约束不因执行面在远端而减少**。

### 3.3 六项核心机制（对应权利要求）

**M1 执行请求与执行标识的服务端生成（对应 S1/S3）**
控制面只提供"技能契约 + 参数 + 截止时间 + 调用方身份"；执行标识与幂等键由**服务端**生成或由服务端
在缺省时生成（仓库实现：`envelope.execution_id` 为空即生成 `exec-<uuid>`，
`src/iraf_adapters/remote/provider_service.py:185`）。缺 deadline 直接拒绝
（`CODE_DEADLINE_MISSING`，同文件 178-180）。

**M2 下发控制量之前的四道校验（对应 S3）**
① 截止时间存在且未过期；② 执行标识是否已处终态（**终态执行的再发控制请求必须被拒绝**，
`CODE_TERMINAL_REUSE`，同文件 193-197）；③ 围栏令牌不得小于该资源已见最大值
（`CODE_FENCING_REGRESSION`，同文件 198-204）；④ 请求能力属于执行面自报清单。
四道校验**全部发生在能力被调用之前**。

**M3 执行域租约 + 单调围栏令牌（对应 S4/S6）**
租约粒度为**单次动作**（execution-scope），TTL 由动作超时决定；冲突即返回资源占用错误且
不无限等待（`CODE_RESOURCE_BUSY`，retryable=True，同文件 212-214）。动作结束——**成功 / 拒绝 / 失败
三条路径**——都必须释放（同文件 `release()` 228-244；释放时若无租约则**不写终态**，
避免把"从未取到租约的调用"记成终态）。释放后下一次动作必须取得**更大**的令牌
（实测第二次调用 `token=2` > 第一次 `token=1`）。

**M4 能力自报 + 装配期单向核对（对应 S2）**
执行面健康查询返回 `ready / simulation / capabilities / inventory`；控制面装配期核对
"声明 ⊆ 实现"（声明缺项即拒，实现多于声明只记录不拒）。实测自报
`capabilities=6 move_joint,pick_object,place_object,reset_scene,stop,visual_pick`。

**M5 同源执行与仿真标识（对应 S5）**
同一份任务编排、场景与判据在两侧复用，只替换执行面与配置声明；仿真标志随结果回传；
仿真专用安全策略不得用于非仿真执行面（仓库：`SafetyPolicy.simulation_only` 在非仿真 profile 上被拒）。

**M6 失败分类与显式拒绝（对应 S6、权项 10）**
`IRAF-RESOURCE-BUSY` / `IRAF-FENCING-TOKEN-REGRESSION` / 终态复用 / deadline 缺失或过期 /
能力未声明，各自独立错误码与中文原因；不允许"重试到成功"，不允许把上次结果当本次。

### 3.4 有益效果（含实测）

| 效果 | 机理 | 实测证据（含来源路径） |
|---|---|---|

## 四、权利要求书草案

### 权利要求 1（独立，方法）

一种控制面与执行面跨机分离的机器人能力调用方法，其特征在于，包括：

S1 在控制面接收任务语义，经任务编排、技能选择与参数校验、策略放行，生成执行请求；
所述执行请求至少包含技能标识、结构化参数、截止时间与调用方身份，且本步骤**不产生任何控制量**；

S2 依据技能声明与资源配置选择执行面，所述执行面为本机执行面或跨机执行面；
选择跨机执行面时，发起携带所述截止时间、幂等键与资源标识的调用；

S3 由**执行面**在**下发任何控制量之前**依次校验：所述截止时间存在且未过期；
所述执行请求对应的执行标识未处于终态；请求携带的围栏令牌不小于该资源已见的最大令牌；
请求的能力标识属于该执行面自报的能力清单；任一校验不通过即拒绝执行并返回与之对应的独立错误码；

S4 执行面为该次动作获取**执行域租约**并取得**单调递增**的围栏令牌；同一资源在同一时刻
仅允许一个活动租约，获取冲突时返回资源占用错误且**不进入无界等待**；

S5 执行面调用所请求的能力，返回执行结果、执行标识、围栏令牌与仿真标志；控制面据其记录
权威执行事实，**不采信调用方或外部模型的自述**；

S6 该次动作在**成功、被拒绝、执行失败三条路径中的任一情况下**均释放所述执行域租约；
释放后同一资源的下一次动作必须取得**大于**前次的围栏令牌；执行标识的终态一经写入不可改写，
重试须由控制面创建新的执行标识。

### 权利要求 2（从属）
如权 1 所述方法，其特征在于，所述截止时间缺失时直接拒绝（不执行"无超时的等待"）；
截止时间已过时拒绝并返回超时类错误码。

### 权利要求 3（从属）
如权 1 所述方法，其特征在于，所述幂等键命中已记录结果时，返回该结果的摘要而**不重复执行**；
幂等键与执行标识的映射由执行面维护。

### 权利要求 4（从属）
如权 1 所述方法，其特征在于，执行面的能力清单由其健康查询**自报**；控制面在装配期核对
"声明的能力集合 ⊆ 自报的能力集合"，声明缺项即拒绝装配，自报多于声明仅记录不拒绝。

### 权利要求 5（从属）
如权 1 所述方法，其特征在于，所述仿真标志随执行结果与控制面记录一并回传；
标注为仿真的安全策略不得用于未标注仿真的执行面，反之亦然。

### 权利要求 6（从属）
如权 1 所述方法，其特征在于，控制面与执行面之间的接口为版本化接口，携带截止时间、取消通道、
健康检查与最小权限凭据；同机部署走子进程标准输入输出，跨机部署走带主机头白名单的流式传输，
凭据缺失时**失败关闭**。

### 权利要求 7（从属）
如权 1 所述方法，其特征在于，**复位类能力与动作类能力共用同一执行域租约域**：
复位成功后立即释放，使紧随其后的动作类请求可在同一资源上被执行面接受，
且仍须取得更大的围栏令牌。

### 权利要求 8（从属）
如权 1 所述方法，其特征在于，执行面为独立进程，与控制面分属不同主机或不同权限域；
当二者合并在同一主机时，进程、运行身份、资源限额与设备所有权四项仍保持分离。

### 权利要求 9（从属）
如权 1 所述方法，其特征在于，安全事件发生后相关资源进入隔离态，
须由控制器确认安全状态并授权复位后才可再次被调度；隔离期间的任何执行请求均被拒绝。

### 权利要求 10（从属）
如权 1 所述方法，其特征在于，所述独立错误码至少区分：截止时间缺失、截止时间过期、
终态执行复用、围栏令牌回退、资源占用、能力未声明；且各错误码附带可操作的中文原因。

### 权利要求 11（独立，系统）
一种机器人能力调用系统，其特征在于，包括：任务编排模块、技能执行模块、策略放行模块、
执行面选择模块、执行域租约与围栏令牌模块、能力自报与核对模块、权威执行事实记录模块；
所述系统被配置为执行权利要求 1 至 10 任一项所述的方法。

### 权利要求 12（独立，存储介质）
一种计算机可读存储介质，其上存储的计算机程序被处理器执行时实现权利要求 1 至 10 任一项所述方法。

## 六、具体实施方式

### 实施例 1（主链路：跨机仿真执行面 + 边缘运行面）

环境：边缘运行面为 aarch64 边缘板卡（Ubuntu 20.04/22.04 档，见板级声明）；
执行面为 x86 主机上的仿真能力提供方（物理仿真 + 图形显示），端点 `10.203.247.121:50052`；
北向为任务级工具接口（提交任务 / 查询执行事实）。

过程：① 外部请求以自然语言任务语义提交；② 运行面在技能契约内选择技能并校验参数，
策略放行后生成带截止时间的执行请求；③ 经版本化接口呼叫执行面；④ 执行面四道校验 → 取执行域租约 →
取围栏令牌 → 仿真执行 → 回传结果、执行标识、令牌与仿真标志；⑤ 运行面据所记录的执行事实回答。

实测（`docs/debug/2026-10-26-x86-sdk-provider-service.md` §4）：
```
ready=True simulation=True capabilities=6
[1] reset_scene accepted 0.08s baseline=initial-snapshot exec=exec-56ac02c3…
[2] move_joint  accepted 0.01s exec=exec-301eb24a…
[3] move_joint  accepted 0.01s exec=exec-bdcccbd0…
总墙钟 0.10s —— 3 次执行互不阻塞、execution 各不相同、无 IRAF-RESOURCE-BUSY
```

### 实施例 2（同机全栈：执行面以服务形式固化）

在 x86 主机按"仿真执行面"安装角色一次安装后：服务单元、装配单、场景、凭据一并落盘，
入口为包内模块（不依赖源码目录）；服务启用即监听 `*:50052`，图形窗口在桌面上（`0x620000b`,
1280x720）；安装物自包含（被引用的资源目录随包安装，引用改写为包内相对路径）。
对应实测：安装退出码 0、记录 9043 个文件；卸载 9050 项、六路残留全 0；
作用域推导若不剔除身份切换与网络目标依赖，则出现 `216/GROUP` 与 `Unit network.target not found`
两例真实失败（同文件 §4.1）——**该两例为"为什么需要作用域推导"的因果证据**，本实施例引用但不主张安装机制本身。

### 实施例 3（拒绝路径，逐条可复跑）

| 场景 | 触发方式 | 期望与实测 |
|---|---|---|
| 资源被上一动作占用 | 上一动作未释放即发起新动作 | `IRAF-RESOURCE-BUSY`、`token=0`、残留租约 `120.0` s（修复前）；修复后 `accepted=True token=2` |
| 终态执行再发控制请求 | 复用已成功的执行标识发起动作类请求 | 拒绝，错误码为终态复用类；非动作类能力不适用该判据（本项目观察项） |
| 围栏令牌回退 | 携带小于已见最大值的令牌 | 拒绝，返回令牌回退类错误码 |
| 截止时间缺失 / 过期 | 执行请求不带 deadline / deadline 早于当前 | 拒绝，返回对应独立错误码；不进入无界等待 |

## 八、替代实施方式与规避设计空间

1. **租约实现**：集中式授权表 / 数据库行锁 / 分布式一致性租约 / 令牌桶 + 版本号，均落入权 1 的
   "执行域租约 + 单调令牌"功能限定；独权不写具体实现，写"同一资源仅一个活动租约 + 释放后须换发更大令牌"。
2. **令牌形态**：单调整数 / 逻辑时钟 / 版本向量；权 1 只要求"单调递增"与"回退被拒"。
3. **传输**：二进制远程调用 / 流式 HTTP / 消息总线动作；权 6 以"截止时间 + 取消 + 健康检查 + 最小权限"
   组合覆盖，不以协议名限定。
4. **执行面替身类型**：物理仿真 / 硬件在环 / 数字孪生 / 云端算力；权 5 以"仿真标志 + 策略互斥"覆盖。
5. **仿真标志的表达**：结果字段 / 独立清单 / 签名声明；权 5 写"随执行结果回传"，不限定字段名。
6. **拒绝码粒度**：可按类或按子类；权 10 要求"至少区分六类"，避免被"合并成一个错误码"规避。
7. **规避风险最高的特征组合（不可回避内核）**：S3 的"下发前四道校验" + S4 的"执行域粒度租约" +
   S6 的"三路径释放 + 释放后须更大令牌"。竞争方案若只做远程调用而无此三者，则 D3/D4 缺陷仍在，
   可据此在意见陈述中强调技术效果差异。
