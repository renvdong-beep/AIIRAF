# 专利交底书：一种机器人应用框架的身份-安全-归属三层解耦的多调用方安全控制方法、系统及存储介质

> 本交底书由 2026-11-05 的《专利方向：身份-安全-归属三层解耦与南北向统一契约》展开，
> 按 13 节骨架成文。所有实测均为仿真/板上 HTTP 实测（`simulation=true`），不构成真机/实时能力证据。

## 一、技术领域

本发明涉及机器人应用框架、机器人操作系统、多调用方安全控制领域，具体涉及一种在机器人应用框架
对外暴露任务级接口（如 MCP）时，把"调用方身份""机器人安全上限""执行归属"三层解耦，并把归属
随执行租约贯穿跨机能力链（南向 Provider）的多调用方安全控制方法与系统。

## 二、背景技术

### 2.1 现有技术格局

机器人应用框架（以 TaskFlow / Skill Manager / Policy Gateway 为核心）对外交付任务级接口，
供上位机 harness、第三方 Agent 平台（如 AgentOS 的 worker）、语音/CLI 前端多方调用；
框架南向通过能力 Provider（仿真 Provider、客户自有 Provider）执行动作。现有技术多采用
"token 即授权"（OAuth/RBAC 类）对北向入口鉴权，并把执行记录写入统一审计日志。

### 2.2 现有技术的具体缺陷

1. **token 即权限，泄露即越权**：安全上限随 token 走，而不是随机器人自身的控制边界（签名
   RobotProfile/SafetyPolicy）走；token 泄露可直接放大到控制权限。
2. **身份不能独立撤销/轮换**：身份与授权耦合，撤销/轮换 token 会连带改变授权，无法"只换身份、不动安全"。
3. **归属停在提交端**："谁提交了任务"止于前端，无法贯穿到跨机执行面（x86 仿真 Provider /
   客户 Provider），审计查不到"谁让哪台机器人做了什么"。
4. **多方共用全局状态串扰**：进程级全局状态（如 robot_mode）被多方共享，跨调用方串状态。

## 三、发明内容

### 3.1 发明目的

提供一种把"身份（谁在调用）""安全（能做什么）""归属（做了什么）"三层显式解耦、各自独立闭环，
并把归属随执行租约贯穿跨机能力链、南北向统一契约的多调用方安全控制方法，解决上述四个缺陷。

### 3.2 技术方案总述

在机器人应用框架的北向任务级入口与南向能力接口之间建立三层解耦：
- 身份层：身份只来自受信 transport，仅用于标识调用方；
- 安全层：安全上限只来自签名 RobotProfile/SafetyPolicy，与身份相互独立；
- 归属层：执行绑定调用方 subject，查询按 subject 过滤，归属随 lease/fencing 贯穿跨机执行面；
- 南北向统一：南向 ProviderKit 与内置 Provider 共用同一 provider.proto 及 LeaseEnvelope，
  lease/fencing/幂等契约与北向一致。

### 3.3 六项核心机制（对应权利要求）

- **M1 身份与安全解耦**：token 只证"你是谁"，不承载任何控制权限；token 泄露/越权也动不了控制边界。
- **M2 安全上限唯一来源**：允许操作由签名 RobotProfile 与 SafetyPolicy 判定，与身份标识相互独立。
- **M3 归属绑定并跨机贯穿**：执行记录绑定 subject，subject 随 lease/fencing 贯穿到跨机执行面。
- **M4 归属过滤与不泄露存在性**：执行查询按 subject 过滤，他人 execution_id 返回 NOT_FOUND，
  不泄露其存在性。
- **M5 多模式凭据隔离**：上位机/AgentOS/Provider/模型网关四套凭据互不复用 + 状态按 subject 分桶。
- **M6 南北向统一契约**：南向 ProviderKit 复用 provider.proto（Health/Invoke/Cancel + LeaseEnvelope），
  lease/fencing/幂等契约与内置 Provider 同一份。

## 四、权利要求书草案

### 权利要求 1（独立，方法）

一种机器人应用框架的多调用方安全控制方法，其特征在于，包括：

S1 从受信 transport 获取调用方身份标识，所述身份标识仅用于标识调用方、不承载安全上限；
对请求体自报的身份信息一律忽略；

S2 依据已签名的 RobotProfile 与 SafetyPolicy 判定所述调用方的允许操作；所述允许操作的
安全上限唯一来源于所述签名声明，与所述身份标识相互独立；

S3 将所述身份标识绑定到执行记录，并随执行租约与围栏令牌贯穿到跨机的执行面（能力 Provider），
使所述执行面在动作前校验租约、围栏与幂等键；

S4 依据所述身份标识过滤执行查询；对不属于该调用方的执行标识返回不存在，不泄露所述执行标识的存在性。

### 权利要求 2（从属）

如权利要求 1 所述的方法，所述身份标识的注册表仅存摘要（SHA-256）、文件权限 600，
并按注册表文件的元组（修改时间、大小、inode、变更时间）热加载，撤销/过期无需重启。

### 权利要求 3（从属）

如权利要求 1 所述的方法，所述允许操作包含任务提交（task.submit）与任务读取（task.read）
两类范围，所述身份标识可绑定资源标识列表，提交时校验资源标识在允许集合内。

### 权利要求 4（从属）

如权利要求 1 所述的方法，多个调用方共享的框架状态按所述身份标识分桶存储，同一时刻
每个身份标识独立持有各自的状态。

### 权利要求 5（从属）

如权利要求 1 所述的方法，所述框架对接四类外部身份（上位机、第三方 Agent 平台、能力 Provider、
模型网关），四类身份凭据互不复用，并分别绑定到不同模式。

### 权利要求 6（从属）

如权利要求 1 所述的方法，当身份标识注册表缺失且未显式启用不安全开关时拒绝启动（失败关闭）；
所述不安全开关仅允许将接口绑定到回环地址。

### 权利要求 7（从属）

如权利要求 1 所述的方法，审计日志记录鉴权通过/失败与工具调用（含执行标识与状态），
且不含所述身份标识的明文与摘要。

### 权利要求 8（从属）

如权利要求 1 所述的方法，所述跨机执行面由南向能力接口承载，该接口与框架内置的能力 Provider
共用同一接口契约（含健康检查、调用、取消与租约信封），其租约、围栏与幂等契约与北向一致。

### 权利要求 9（从属）

如权利要求 8 所述的方法，所述南向能力接口允许客户自有控制器/仿真器以独立进程接入，
并接受与内置 Provider 相同的租约信封校验。

### 权利要求 10（从属）

如权利要求 1 所述的方法，所述身份标识经 transport 的 Bearer 头或进程环境传入，
不经工具参数传入。

### 权利要求 11（独立，系统）

一种机器人应用框架的多调用方安全控制系统，包括处理器与存储器，用于执行如权利要求 1 至 10
任一项所述的方法。

### 权利要求 12（独立，存储介质）

一种计算机可读存储介质，其上存储有程序，所述程序被处理器执行时实现如权利要求 1 至 10
任一项所述的方法。

## 六、具体实施方式

### 实施例 1（主链路：上位机 → MCP → Policy → 跨机 Provider）

上位机 harness 携 `Authorization: Bearer <opaque token>` 访问任务级 MCP；MCP 中间件
从 transport 取身份（S1），经 Policy Gateway 以签名 RobotProfile/SafetyPolicy 判定允许操作（S2），
生成执行并绑定 subject（S3）；执行经南向 ProviderKit 以 provider.proto 的 LeaseEnvelope 下达到
x86 仿真 Provider，Provider 在动作前校验租约/围栏/幂等（S3/S6）；审计 JSONL 记录鉴权与工具调用（S4）。

### 实施例 2（多调用方隔离：A/B 归属）

调用方 A 与 B 各持不同 token；A 提交得到 execution_id=287191a0-…，B 的 token 以相同
execution_id 调用读取接口，返回 NOT_FOUND（S4）；A、B 的 robot_mode 状态按 subject 分桶互不串扰（S5）。

### 实施例 3（拒绝路径，逐条可复跑）

- 无 token/失效 token ⇒ 401（S1）；
- 仅 task.read 的 token 提交 ⇒ `IRAF-POLICY-DENIED`，无动作、无 execution_id（S2）；
- 缺注册表启动 ⇒ 退出 2；`INSECURE=1` 绑 0.0.0.0 ⇒ 拒绝（S1/S6）。

## 八、替代实施方式与规避设计空间

- 只做 Bearer 鉴权、不拆身份/安全两层 ⇒ 规避 S1+S2；
- 只做审计日志、不把归属贯穿到跨机执行面 ⇒ 规避 S3；
- 只做 OAuth scope、不以签名 Profile/Policy 为唯一安全上限 ⇒ 规避 S2；
- 只做多租户、不做执行标识不存在性不泄露 ⇒ 规避 S4；
- 南北向分开两套鉴权、不统一 lease/fencing ⇒ 规避 S8/S9。
