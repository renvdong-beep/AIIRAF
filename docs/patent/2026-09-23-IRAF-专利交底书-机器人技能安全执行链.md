## 一、技术领域

本发明属于机器人控制与智能体（Agent）/大语言模型应用交叉领域，具体涉及一种在大模型或智能体作为任务发起方时，把**语义化任务意图**安全、可审计、可恢复地转化为**物理执行器动作**的方法与系统；适用于工业机械臂、移动机器人、四足/人形机器人及其多机协同场景。

## 二、背景技术

### 2.1 现有技术格局

1. **机器人底层与执行层**：ROS 2、MoveIt 2、ros2_control、Nav2 已成事实标准，负责规划、逆解、轨迹插值与局部闭环。它们解决"怎么动"，不解决"谁有权让它动、动到什么边界、失败后能否照样复现"。
2. **声明式硬件资源与设备管理平台**（如 Viam）：把硬件抽象为可声明资源并提供统一 API、模块注册与云侧版本化部署，提升了集成体验；但其控制面在云/局域网，实时与安全边界不在其职责内。
3. **快慢策略协同运行时**（如 OpenRAL）：提出快策略 + 慢推理 + 传统控制的类型化编排，方向与本方案接近，但相对较新，未形成"身份—策略—资源—终态—复位"的完整可审计执行链。
4. **学习策略与数据集接口**（如 LeRobot）、**车队调度**（如 Open-RMF）、**加速感知**（如 NVIDIA Isaac ROS）：分别覆盖策略/数据、多机分派、异构加速，均为局部能力。
5. **厂商官方栈**（如宇树 Go2 的 `unitree_mujoco` / `unitree_ros2`）：提供模型、消息与低层仿真示例，主要覆盖低层控制，不含任务治理、安全准入与跨本体事务。
6. **通用"大模型 + 机器人"方案**：多为"语言模型输出目标点/动作 → 直接调用技能/接口执行"。其共性问题是在模型输出与执行器之间缺少**不可旁路、可证明、可复现**的管控层。

### 2.2 现有技术的具体缺陷

| 编号 | 缺陷 | 后果（现场可观察现象） |
|---|---|---|
| D1 | 模型/应用输出与执行器之间缺少不可旁路的准入层；参数与安全边界由调用方拼装 | 越权提速、越界工作空间、绕过互锁；"模型说能做"即被当作能做 |
| D2 | 身份来自请求体（caller/role 字段）或由编排器系统身份代表用户 | 伪造身份、编排器提权（编排器把自己用户本没有的技能执行权"放大"给下游） |
| D3 | 重试/重连缺乏服务端统一执行标识与幂等域 | 同一物理动作被重复下发（物体被重复抓取、重复移动、重复放件） |
| D4 | 租约只做互斥、不做围栏（fencing）；切换控制源后旧控制者仍可写通道 | 分区/超时后旧控制者的迟到指令继续驱动执行器（最危险的失效之一） |
| D5 | 失败执行可被"复活"或迟到成功回调改写终态 | 事故复盘时执行记录与物理事实不符；掩盖真实故障 |
| D6 | 求解型控制器（MPC/QP）超时或无解时"沿用上一拍解" | 过期状态驱动执行器，行为不可解释；风险随负载上升而隐性放大 |
| D7 | 仿真与真机能力不区分、配置中的"未验证"值被当作可用值 | 仿真结果被表述为真机能力；上线即失效且无人预警 |

上述缺陷共同指向一个技术问题：**当任务发起方是概率性、不可解释、可被提示注入影响的智能体时，如何保证物理执行仍然只受确定性的、可证明的、可复现的约束支配。**

## 三、发明内容

### 3.1 发明目的

提供一种机器人技能安全执行方法，使得：

1. 智能体/大模型的输出**只能作为受约束的意图**进入执行，且**不存在旁路**；
2. 外部输入对安全边界**只能收紧、不能放宽**（单调性可证明）；
3. 每一物理动作**有且仅有**一个服务端权威执行标识与一个控制源，重复请求不产生重复动作，旧控制者不能驱动新执行；
4. 执行终态**不可复活、不可被回调改写**；失败只能以上层新建执行的方式恢复，并保留因果链；
5. 任何"求解失败/状态过期/时钟异常"都走**显式降级到安全保持**，绝不沿用过期控制量；
6. 安全事件后资源**隔离**，仅在三项条件同时满足时才允许复位。

### 3.2 技术方案总述

系统由控制面（与硬件无关，跑在通用 Linux）与边缘面（适配器，唯一可接触 ROS 2/厂家 SDK/现场总线）构成。请求的强制路径为：

```text
智能体/应用
   │  ① 结构化技能请求（不含可信身份字段）
   ▼
受信传输层 ── 构造 AuthenticatedContext（主体/租户/角色/凭据ID/认证时刻）
   │
   ▼
Skill Runtime ── ② 服务端生成 execution_id、绑定幂等键与请求摘要
   │
   ▼
Policy Gateway ── ③ 固定顺序、不可交换的准入决策链（八步）
   │               身份 → 角色/租户 → 请求结构 → 技能前置条件
   │               → 参数可覆写范围 → 本体配置快照 → 安全策略
   │               → 能力/运行状态 → 执行授权
   │            （④ 合并语义：外部参数只能收紧安全约束）
   ▼
Resource / Authority ── ⑤ 两级资源租约 + 单调围栏令牌 + 全局获取顺序
   │
   ▼
运动许可门 ── ⑥ 控制器心跳（单调序号）+ 与围栏令牌绑定的短寿命运动许可
   │
   ▼
能力提供者（传统算法 / 学习策略 / VLA / 遥操作 / 回放）
   │  ⑦ 策略输出统一为 ActionProposal，经归一化 + 安全投影后才进入确定性执行器
   ▼
确定性执行器 / 控制器（本地、有界、带时间戳与看门狗）
   │
   ▼
执行台账 ── ⑧ 单调序号、终态写一次、围栏令牌校验；安全事件 ⇒ 资源隔离
```

核心机制可概括为**"六重门 + 一条台账"**：身份门、契约门、策略门、资源门、许可门、复位门，以及一条只追加、终态写一次的**执行台账（execution ledger）**。

### 3.3 六项核心机制（对应权利要求 1 及各从属权利要求）

#### 机制一：身份不可伪造 + 固定序决策链 + 参数单调收紧

- 身份只来自受信传输（mTLS/JWT interceptor 构造的 `AuthenticatedContext`，含 subject/tenant/roles/credential_id/认证时刻），**请求体中的 caller/role/tenant 一律不参与授权**。
- 准入决策链的顺序固定且不可交换（见 3.2 ③），任一步失败都**不产生任何面向执行器的控制量**（fail-closed）。
- 参数合并是**单调收紧**的：`最终约束 = 安全策略约束 ∩ 本体配置约束 ∩（调用方参数给出的更严约束）`。调用方可提出更小速度、更短时长；**不存在**任何使最终约束大于安全策略上限的输入路径。
- 每次允许/拒绝生成不可变的 `PolicyDecision`（规则 ID、输入摘要、配置/策略摘要、最终约束集合、trace ID），且不记录原始图像、密钥或不必要的个人数据。

#### 机制二：服务端执行标识 + 幂等域 + 短时签名委托（防提权）

- `execution_id` 由**服务端**生成（幂等键存在时由 `(主体, 幂等键)` 确定性派生），调用方不得指定。
- 幂等键的唯一域为 `(authenticated_subject, tenant, operation)`：同键同摘要 ⇒ 返回原执行流/快照，**不重复执行**；同键不同摘要 ⇒ 返回幂等冲突错误且**不下发任何动作**。
- 编排器（TaskFlow 引擎）调用下游时使用**短期签名委托** `TaskDelegation`，其中固定 task_id、原始认证主体、允许的技能与版本、本体/策略摘要、资源范围与到期时间。校验时**同时**验证编排器自身工作负载身份与委托约束；编排器的系统身份不得放大原调用者的权限。
  **【设计稿】**：`TaskDelegation` 的字段与校验语义已在设计基线中写死（`docs/iraf-taskflow-policy-detailed-design.md` §3），代码尚未落地。

#### 机制三：两级资源租约 + 围栏令牌 + 执行台账（终态写一次）

- 租约含 `resource / owner / TTL / 单调递增 fencing_token`。分两级：
  - **任务级租约**：跨步骤独占物理区域（例：交接区 `handoff_zone`）；
  - **执行级租约**：单次动作独占执行器（例：`piper.arm`、`quadruped.base`）。
- 多级租约按**声明式全局获取顺序**获取，避免死锁；竞争失败返回"资源忙"错误而**不无限等待**。
- 每次运动调用前，在执行台账中校验（且**在下发任何控制量之前**完成）：执行是否仍在活动态、租约是否仍是**同一**围栏令牌、能力是否与台账记录一致。旧令牌、终态执行的续跑请求一律拒绝。
- 台账的状态写**只能写一次**：`SUCCEEDED/FAILED/CANCELLED/SAFETY_STOP/STOPPED` 一旦写入，迟到的成功回调不得改写。

#### 机制四：运动许可门（心跳 + 围栏绑定 + 短寿命许可）

- 控制器以**单调递增序号**上报心跳；序号不增或超时 ⇒ 拒绝运动。
- 运动许可由控制器侧授予，与**围栏令牌绑定**且**短寿命**（含到期时刻）；许可的资源不匹配、令牌不匹配或已过期 ⇒ 拒绝运动。
- 该门使"控制面（可被网络分区）"与"执行面（必须确定性）"解耦：控制面失去心跳，执行面自己关门。

#### 机制五：控制解新鲜度门禁与双停止语义（禁止复用旧解）

- 求解型控制器（MPC/QP）的解带时间戳。消费侧在使用前判定解龄：解龄超过**声明的 N 个控制周期**（实施值：2 × 20.0 ms = 40.0 ms）、或解龄为 `None/NaN/Inf/负值`（时钟异常，一律视为不可信）、或求解状态分类不属于"可用"集合 ⇒ **停止使用该解**并进入保持。
- 失败路径**不输出任何解**（`z = None`），即禁止"沿用上一拍解"。求解器运行在独立进程/独立环境：超时、崩溃、输出非法一律返回"保持"决定且不返回解；急停/安全事件则作废解。
- 停止语义按"是否在移动 / 是否安全事件"分流为二：
  - **阻尼保持（damped_hold）**：移动中收到停止、或移动中求解失败 ⇒ 指令速度置零并按声明加速度上限减速，**保持站立位形**、保持控制权；
  - **力矩释放（torque_zero_release）**：急停/安全事件 ⇒ 最高优先级，直接释放力矩。
  - 若保持过程超时仍未达标（末速、倾角、机身高度三条判据），**显式失败**并上报最后状态，不得静默继续、不得报成功。

#### 机制六：安全事件隔离与三条件复位

- 收到安全事件后：相关执行置 `SAFETY_STOP`、相关资源转入 `QUARANTINED`、拒绝新动作，并请求本地控制器安全停止；正在运动或未确认 safe state 的资源**不得提前释放**。
- 解除隔离需**同时**满足三项，缺一即拒绝：
  1. 安全事件标识与隔离记录**一致**（防止复位"另一个"事件）；
  2. 本地控制器回送**safe-state 确认**；
  3. 具备复位权限的**经认证操作者**提交复位（角色来自受信传输，非请求体）。
- 复位后重新生成新的围栏令牌；旧执行**永久保持终态**。

| 交付物可逐位复现（含跨架构） | 集中声明 + 离线 wheelhouse + 双次构建对比 | SDK 产物连续两次构建 SHA-256 逐位相同（`docs/iraf-engineering-design.md` §3 表） |
| 抓取精度满足并留有余量 | 声明式几何/前馈/夹持区 + 视觉链路 | Piper 验收：接触力 `0.240676 / 0.244112 N`、抬升 `0.087184 m`、位姿偏差 `0.002826042685491991 m`（容差 0.005）；随机化 25 次采样位置误差均值 `0.963 mm`、最大 `1.773 mm`，姿态 `0.880°` / 最大 `1.480°`（`docs/display-and-randomization-contract.md` §2.5） |

- 上表"P50 16.899 → 7.84 ms / 越界 9 → 0"的**原因**是等价缩放 + 原生 OSQP + 参考轨迹保值摊销三项改动，**不是**阈值放宽；判据（P99 ≤ 15.0 ms、越界 = 0、max ≤ 20.0 ms）在改造前后**完全不变**。
- `max_tilt_deg = 0.32191154615220985`（保持过程）与 `max_tilt = 2.7679°~2.7836°`（trot 直行）是**不同工况**的两个量，不可互换引用。

## 四、权利要求书草案

### 权利要求 1（独立权利要求，方法）

一种智能体驱动的机器人技能安全执行方法，所述机器人包括至少一个由执行器驱动的本体，其特征在于，包括：

**S1** 接收来自智能体或应用的技能请求，所述请求包含技能名称、技能版本约束、以结构化数据表达的任务参数、截止时间与幂等键；所述请求**不包含**用于授权的身份字段；

**S2** 由受信传输层依据传输层凭据构造认证上下文，所述认证上下文至少包含主体标识、租户标识、角色集合与认证时刻；当且仅当所述认证上下文通过校验时继续，否则以统一的未认证错误码显式失败并且不产生任何控制量；

**S3** 按**固定且不可交换的顺序**执行准入决策链：角色与租户授权、请求结构校验、技能清单前置条件、参数可覆写范围、本体配置快照、安全策略、能力与运行状态、执行授权；其中，(i) 所述决策链的任一步失败均不产生面向执行器的控制量；(ii) 所述技能请求携带的执行偏好与任务参数在与所述本体配置快照和所述安全策略合并时，**只能使最终约束集合单调收紧，不能放宽**；

**S4** 由服务端生成执行标识，并在（主体、租户、操作）唯一域内将所述幂等键与所述技能请求的摘要绑定；当同一幂等键对应不同摘要时返回幂等冲突错误且**不向执行器下发任何动作**；当同一幂等键对应相同摘要时返回既有执行记录而不重复执行；

**S5** 在执行前获取资源租约，所述资源租约至少包含资源标识、属主、有效期与**单调递增的围栏令牌**；所述资源租约包括用于跨步骤独占物理区域的任务级租约与用于单次动作独占执行器的执行级租约，多级租约按声明式全局顺序获取，竞争失败返回资源忙错误而不无限等待；

**S6** 将所述围栏令牌与所述执行标识写入执行台账；对同一执行的后续控制请求，**在下发任何控制量之前**校验该执行是否仍处于活动态、所述资源租约是否仍为同一围栏令牌、以及请求的能力是否与台账记录一致，任一不满足即拒绝该控制请求；

**S7** 在收到安全事件时，将相关执行置为安全停止终态、将相关资源转入隔离态并拒绝新动作，并请求本地控制器执行安全停止；仅当安全事件标识与隔离记录一致、所述本地控制器回送安全状态确认、且具备复位权限的经认证操作者提交复位请求这三项同时满足时，才允许解除隔离；

其中，所述执行台账中的终态一经写入不可被后续回调改写，包括迟到的成功回调；失败后的重试或恢复由上层编排器创建新的执行标识并保留指向原执行的因果关联，而非复活原执行。

### 权利要求 2（从属，防提权委托）

根据权利要求 1 所述的方法，其特征在于，所述上层编排器调用所述执行过程时附带有期限的签名委托，所述签名委托固定任务标识、原始认证主体、允许的技能与其版本、本体配置与安全策略摘要、资源范围与到期时间；校验时同时验证编排器自身的工作负载身份与所述签名委托的约束，使编排器的系统身份不能扩大所述原始认证主体的权限。

### 权利要求 3（从属，版本快照冻结）

根据权利要求 1 所述的方法，其特征在于，将技能、能力提供者、本体配置与安全策略的标识、版本与摘要作为不可变快照写入执行记录；执行恢复时不重新解析技能版本，且当请求声明的本体配置或安全策略的名称、版本、摘要与本地快照任一不匹配时拒绝执行。

### 权利要求 4（从属，运动许可门）

根据权利要求 1 所述的方法，其特征在于，所述本地控制器以单调递增序号上报心跳，并由所述本地控制器授予与所述围栏令牌绑定且具有到期时刻的运动许可；在下发运动控制量前，当心跳缺失或超时、心跳序号未递增、运动许可的资源或围栏令牌不匹配、或运动许可已过期时，拒绝下发。

### 权利要求 5（从属，能力契约单向校验）

根据权利要求 1 所述的方法，其特征在于，在装配期校验"本体配置声明的能力集合 ⊆ 能力提供者实际实现的能力集合"，声明了而未实现的能力导致装配失败；实现而未声明仅记入装配报告供审计，不导致装配失败且不使该能力对外可用。

### 权利要求 6（从属，未验证配置与仿真标识）

根据权利要求 1 所述的方法，其特征在于，当技能、本体配置或安全策略的验证状态不为已验证时，仅在所述本体配置标记为仿真时允许执行，否则拒绝；标记为仿真专用的安全策略在非仿真本体上被拒绝；并且执行结果中回传仿真标识，禁止将仿真结果表述为真机能力。

### 权利要求 7（从属，不可变策略决定）

根据权利要求 1 所述的方法，其特征在于，每次允许或拒绝均生成不可变的策略决定记录，所述记录包含规则标识、输入摘要、本体配置与安全策略摘要、合并后的最终约束集合与追踪标识，且不记录原始图像、密钥或非必要的个人数据。

### 权利要求 8（从属，规则合并次序）

根据权利要求 1 所述的方法，其特征在于，多条策略规则冲突时按"拒绝优先、约束取交集、权限取最小"的顺序合并。

### 权利要求 9（从属，受限表达式语言）

根据权利要求 1 所述的方法，其特征在于，所述前置条件、守卫条件与互锁条件使用同一种受限表达式语言，所述语言仅允许字段引用、字面量、比较运算、逻辑运算与集合包含判定，禁止函数调用、输入输出、时间读取、循环与动态求值；表达式编译器的版本被写入执行计划。

### 权利要求 10（从属，控制源单写者仲裁）

根据权利要求 1 所述的方法，其特征在于，同一执行器的控制权在同一时刻仅由一个控制源持有，控制源在传统算法、学习策略、视觉语言动作策略、遥操作与回放之间切换时，须先停止接收原控制源的候选动作、等待确定性轨迹停止或完成、确认安全保持、再生成新的资源租约与围栏令牌；策略输出的候选动作先被归一化为统一的动作提案结构，经所述准入决策链与安全投影后才进入确定性执行器。

### 权利要求 11（从属，控制解新鲜度门禁与双停止语义）

根据权利要求 1 所述的方法，其特征在于，对由求解器周期性生成的控制解，在消费侧判定其解龄：当解龄超过声明的控制周期倍数、或解龄不可信、或求解状态分类不属于可用集合时，停止使用该控制解并且不输出任何控制解；并且按下述规则选择停止语义：处于移动状态时选择"减速到零并保持位形"的阻尼保持，处于急停或安全事件时选择力矩释放；当阻尼保持在声明的停止时限内未满足末速、倾角与机身高度判据时，输出显式失败与最后测量状态。

### 权利要求 12（从属，求解器进程隔离）

根据权利要求 11 所述的方法，其特征在于，所述求解器运行在独立于控制面的进程中，当所述进程超时、崩溃或输出非法时，返回保持决定且不返回控制解；收到急停或安全事件时作废当前控制解，须重新求解后才可能产生可用解。

### 权利要求 13（独立权利要求，系统）

一种机器人技能安全执行系统，其特征在于，包括：

- **受信传输入口**，用于依据传输层凭据构造认证上下文，并拒绝请求体中声明的身份；
- **策略网关**，用于按固定且不可交换的顺序执行准入决策链，并在合并参数时仅允许收紧安全约束；
- **技能运行时**，用于生成服务端执行标识、在（主体、租户、操作）域内绑定幂等键与请求摘要、并维护只追加且终态写一次的执行台账；
- **资源协调器**，用于发放含单调围栏令牌的两级资源租约，并在下发控制量前校验执行活动态、围栏令牌与能力一致性；
- **控制权与许可门**，用于实现单一写控制源仲裁与基于控制器心跳及短寿命许可的运动准入；
- **隔离管理器**，用于在安全事件后隔离资源，并仅在三条件同时满足时解除隔离；
- **能力适配层**，为唯一可访问机器人中间件、厂家软件开发包与现场总线接口的模块；

所述系统被配置为执行权利要求 1 至 12 任一所述的方法。

### 权利要求 14（独立权利要求，存储介质）

一种计算机可读存储介质，其上存储有计算机程序，其特征在于，所述计算机程序被处理器执行时实现权利要求 1 至 12 任一所述的方法。

## 六、具体实施方式

### 实施例 1：机械臂抓取（单本体，视觉闭环）

**环境**：Ubuntu 22.04 + ROS 2 Humble + MuJoCo（`simulation=true`）；本体 Piper（眼在手相机）与 UR5e+2F-85 双机型共用同一套核心逻辑。

**执行过程**：

1. 应用提交 `pick_object` 请求（含 `object_id`、`idempotency_key`、`correlation_id`、`deadline`、Profile/Policy 名称-版本-摘要）。
2. 传输层构造认证上下文（`transport ∈ {bearer, local}`）；缺失即 `IRAF-UNAUTHENTICATED`。
3. 策略网关按固定八步校验：角色须含 `task.submit`；`request_id`/`correlation_id`/`idempotency_key` 三者必填；Schema 校验；Profile 与 Policy 的名称/版本/摘要三比对；未验证配置仅限仿真；安全策略许可清单；能力集合 `declared ⊆ implemented`；动作时长取 `min(技能清单超时, 安全策略时长上限)`。
4. 资源租约（执行级）发放；围栏令牌写入台账；校验通过后下发，反馈流携带单调 `sequence` 与终态原因。
5. 结果冻结回放边界元数据（技能/提供者/Profile/Policy 版本与摘要、`policy_decision_id`、`simulation` 标志）。

**实测结果**：接触力 `0.240676 / 0.244112 N`、抬升 `0.087184 m`、位姿偏差 `0.002826042685491991 m`（容差 0.005）；随机化 25 次采样位置误差均值 `0.963 mm`、最大 `1.773 mm`、姿态 `0.880° / 最大 1.480°`。

**跨本体验证（对应 P4）**：UR5e 未接入视觉提供者时，Profile 诚实声明 `[move_joint, pick_object, stop]`；装配报告记录 `undeclared_motion_capabilities=["visual_pick"]`、`passed=true`；提交 `visual_pick` ⇒ `FAILED / IRAF-SKILL-PROVIDER-UNAVAILABLE`，**在策略层被拒**（原因字符串：`RobotProfile 缺少能力: ['visual_pick']`）。

### 实施例 2：机械臂—四足交接（多本体协同）【部分为设计稿】

**已实现部分**：两本体各自的能力契约、状态反馈键与安全上限声明化（`profiles/safety/quadruped_lab.yaml`：`max_speed_mps = 0.5`、`max_yaw_rate_rad_s = 1.0`、`max_base_translation_m = 0.05`、`max_tilt_deg = 10.0`、`max_tilt_moving_deg = 15.0`、看门狗 `100.0 ms`）；任务级/执行级两级租约与全局获取顺序（设计值 `acquisitionOrder: [handoff_zone, quadruped.base, piper.arm]`）。

**【设计稿】**：交接区互锁（放件前须满足"狗 `speed == 0` 且姿态稳定且托盘可用"）已在安全策略与安全论证中给出规则与危险分析（`docs/iraf-safety-case.md` H-01 四重互锁、`docs/iraf-taskflow-policy-detailed-design.md` §3 `interlocks`），**实现待落地**；本交底书不将其作为已实施证据。

## 八、替代实施方式与规避设计空间（撰写权利要求时须覆盖）

1. **租约实现**：可由单进程内存协调器（本实施）、集中式协调服务、或基于共识（Raft/ZooKeeper）的协调器实现；围栏令牌可用单调计数器、纪元号（epoch）或逻辑时钟实现——权利要求应以功能限定（"单调递增的围栏令牌"）而非具体实现措辞保护。
2. **幂等实现**：可用数据库唯一约束、事件存储去重、或分布式键值实现；摘要算法不限 SHA-256（权利要求应写"请求摘要"）。
3. **解新鲜度阈值**：本实施取"2 个控制周期"，但权利要求应限定为"声明的周期倍数"，覆盖 1、3、N 倍等替代；解龄判定可用时间戳差、序号差或混合方式。
4. **停止语义命名**：`damped_hold` / `torque_zero_release` 为工程命名，权利要求应使用功能性表述（"减速到零并保持位形" / "释放力矩"）。
5. **决策链顺序**：权利要求已限定"固定且不可交换的顺序"并给出八步；应保留"其中能力与运行状态校验可拆分为能力校验与健康校验两步"的等同实施空间。
6. **安全投影**：可位于策略网关内部、独立服务、或执行器侧固件；权利要求应覆盖三种部署形态。
7. **本方案的"反向规避"风险**：竞争者可能通过"把部分门禁下移到适配器/固件"来规避；因此权利要求 1 的 S6（**下发任何控制量之前**校验活动态/围栏令牌/能力一致性）与 S5（两级租约 + 单调令牌）必须同时保留，二者共同构成"控制权可证明归属"的不可规避内核。
